The fixed target is January 2–8, 2024 UTC. January 1 retained data supplies the first prior-hour overlap and the identical-population compression benchmark. ## Frozen source and accounting

The prior inventory selects exactly one current archive object per required date/table by full key, size and ETag. Conditional anonymous requests use that identity; no relisting, retries, alternate sources, paid resources, credentials or date substitutions are permitted. All network attempts are journaled before I/O and retain response prefixes on ordinary errors. Denial stops further network acquisition globally. No subsequent empirical reattempt is admitted by this charter.

Limits: 2,100 actual requests; 2 GiB total newly received body bytes; 32 MiB response payload limit with at most one overflow detection byte; the sentinel byte is reserved inside the hard aggregate byte allowance. Each target day allows 272 MiB captured bytes, including blocks/footer, at most 291 requests, at most 256 MiB selected transaction columns, 16 MiB full block object, 4 MiB footer metadata plus 8 trailer bytes, 32 row groups, 2,000,000 transaction rows and 8 GiB logical sparse object size. The closing block object has the same 16 MiB limit. Cap exhaustion is unavailable; no resizing, substitution or partial-day admission. Failed/partial receipts, orphan blobs and intents remain evidence. Network operations retain their 30-second timeout.

Transaction columns are hash, block_hash, block_number, block_timestamp, transaction_index, from_address, to_address, value and receipt_status. Native top-level positive successful transfers excluding self-transfers are graph events. Exactly the literal recipient string `None` is normalized to null, with the count reported; other invalid addresses fail integrity. DOUBLE value is used only for eligibility, never exact-wei accounting or monetary inference. Every transaction hash and block position must reconcile; exact transaction hashes are also checked across all available source days including January 1, with coverage reported; block counts, hashes, timestamps and schema must pass. Adjacent block height, parent hash and time are checked across both day boundaries. These are internal archive consistency checks, not independent canonical-chain validation.

## Storage and durable lifecycle

Use deterministic zstd level 3 with content size and checksum. Every blob records raw/stored lengths and SHA-256 and undergoes bounded decompression roundtrip verification. Acquisition intents precede the request; immutable blob and receipt publication follows using fsync and exclusive linking. Old base64 JSON receipts are never replaced. Compare the same 117 retained January 1 projected byte ranges as existing JSON receipts, raw binary payload, theoretical base64 payload, and zstd payload. Report metadata and derived-artifact overhead separately. The one-day baseline and seven target days do not establish a three-year compression ratio or fit.

The normal ResearchRun helper retains its original implementation. Its registered JSON outputs bind the separate binary artifact tree through a final complete file manifest. Workers verify each registered prior input SHA-256 at read and each generated compressed blob at use; lifecycle start, JSON publication and finish revalidate registered sources/inputs/history. Source and input paths are frozen in plan/gate. Incomplete artifacts remain if a process is killed before the terminal manifest. Before finish, every intent must have a receipt, every compressed blob must have a metadata binding, every raw/stored hash must pass decompression verification, and every artifact must enter the final manifest. Structural lifecycle verification alone cannot certify the separate binary tree; independent manifest/raw verification is required. Preserved detached execution HEAD remains unchanged. Imported immutable evidence may be hardlinked between local checkouts, then committed/pushed and remote hash verified; local duplication is not external backup.
