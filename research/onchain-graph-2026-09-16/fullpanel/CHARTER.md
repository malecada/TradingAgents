retrospective engineering run, not a forecasting or financial trial. Exactly
1,096 UTC dates, January 1, 2022 through December 31, 2024, remain in the output
denominator. The thirteen predecessor claims, failed attempts, source stores,

## Numerical and independent checks

The pilot's nine columns, successful positive non-self top-level native-transfer
eligibility, literal recipient None normalization and stable integer-second/order
conventions are unchanged. DOUBLE value is only an eligibility flag, not exact-wei
accounting. Preserve per-day source identity, uniqueness, block counts, ordering,
schema, graph activity and event/hash/prefix digests.

The same Local40 code counts inclusive 3,600-second spans, assigns occurrences
to completion day and retains overlap-only nodes. Ordinary activity, all role
sums/squares/maxima/nonzero/concentration summaries, isolated-day diagnostics,
cross-midnight differences and fixed top-three-boundary-address brute-force
subsets remain. Before temporary arrays are released, an independent subprocess
rereads each raw day, checks exact events/hashes/prefix and annotation schema,
verifies both raw block boundaries, independently recounts all completion-day
and cross-midnight dyads, recomputes local-vector summaries and independently
checks bounded full-role subsets. Full-day stars/triangles are not exhaustively
independently recounted. Earlier qualifier-comparison corrections remain explicit.

Exact cross-day uniqueness includes every transaction on all 1,096 source dates
once, including both graph-unavailable edges and reused pilot days. Full 32-byte
identities enter 256 leading-byte buckets; no truncation, Bloom filter or partial
population substitutes. Each append binds day index, ordered stream digest,
count and exact per-bucket byte segments. One bucket at a time is checked and
sorted using the reviewed in-place heapsort design. A separate post-terminal
checker independently reconciles every bucket and its duplicates using a
different sort, exact day/segment population, output hashes and retained reports.
Any duplicate or missing source blocks admission of the whole feature panel;
there is no favorable-date exclusion. Hash scratch remains until that closure.

## Storage, resources and preservation

Use the pinned Python/lock environment, two CPUs and 8 GiB sampled aggregate
process-tree RSS, with no elapsed-time kill. Source/count and independent daily
checks run in separate subprocesses. The guard can miss very brief RSS peaks.
Per-phase disk checks require at least 20 GiB free on both volumes. New Data
retained numerical artifacts and run metadata have a 2 GiB ceiling, and one-day
recomputable arrays have a separate 2 GiB ceiling, checked between phases.
Sparse projected files use Data temporary storage. These are phase-boundary
checks, not atomic filesystem quotas; overruns remain preserved evidence.

The root filesystem has a new, exclusively owned exact-hash scratch directory
specified in plan.json, with a 40 GiB allocated-byte ceiling. The expected
36.4003 GiB payload leaves metadata/slack within it. Hash append checks the
20 GiB free-space floor plus a 1 MiB margin before each write, and limits each
bucket to the reviewed 256 MiB and each input chunk to 32 MiB. An oversized
bucket or storage shortfall stops the run; limits do not silently expand.

Raw captures, previous derived evidence and source metadata are never deleted.
Only newly generated events, transaction hash shards and per-address Local40
arrays under fullpanel/artifacts/scratch/DATE are explicitly recomputable and
disposable. They may be removed only after the independent daily report,
exact-hash append receipt, full temporary-file digest manifest and immutable
daily lifecycle output have been published. Every prefix, compact daily result,
local/vector digest, bounded oracle, daily report, append receipt and cleanup
receipt remains. Cleanup validates exact ownership, membership, sizes and
hashes; a failed day keeps its temporary evidence. Global hash buckets remain
for separate independent closure and may be released only after that report,
terminal and complete manifests are durable. Failed appends/buckets are retained.
