## Verification and release conditions

At review, all 68 draft source bindings and 2,919 existing input bindings match
their actual bytes. Focused results supplied by the implementing agents are
34 guard tests, 39 final-checker tests, 16 policy tests and nine runner tests,
plus a tiny equal-high/max kernel-control check. This review inspected those
test definitions and source parity; it did not rerun the reported tests or
treat them as real-workload evidence. The full named offline target is still
a release prerequisite.

Before any new claim:

1. Complete the gate with this review, approval, exact amendment and successful
   named offline verification. Validate all source/runtime/input bindings,
   the fifteen-claim history, full denominator and exposed-sample lineage.
2. Commit the complete contract and reviewed source, verify the exact commit
   remotely, prepare the exclusive resume2 checkout at that source and pass
   standard admission there.
3. Confirm no active predecessor or successor compute/review owner; require
   fresh resume2 artifact, hash and resource namespaces and the preserved
   excluded predecessor hash root still empty.
4. After launch, verify actual kernel controls, PID/start/boot/unit ownership,
   the current lease and byte-identical seed republication. Distinguish that
   restoration from newly completed source dates.

These are release checks within the user's standing continuation authority,
not a request for repeated permission. Any change to reviewed source or
criteria requires updated bindings and review before claim.

The actual continuation, real-workload resource sufficiency, final global
uniqueness, exhaustive full-day stars/triangles, canonical-chain proof,
