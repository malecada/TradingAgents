## Selected behavior

The new protected branch is selected only by non-null `native_unit_limits`. It imports the canonical `tradingagents.research.onchain_replication.owned_io` and uses its actual `CleanupFailure`, `_fatal` and `_flatten` semantics. It does not identify cleanup errors by class name, fabricate a physical scope or activate `physical_policy`.

The selected body error is stored before diagnostic formatting. First actual fatal identity is retained across later fatal exceptions, including genuine cleanup wrappers containing an earlier fatal. Genuine cleanup uncertainty is not demoted to an ordinary error. Diagnostic failure cannot replace an already selected actual fatal. Failed storage observations use the same protected selection.

Each native finalization action is attempted independently: ignore each signal, stop the unit, read unit properties, read cgroup population, verify the combined stop/readback, observe storage, check the final disk floor, publish, restore each prior signal, attempt the exclusive final receipt, and synchronize its directory. A stop exception does not suppress readback. Cleanup verification remains false unless every stop/readback component succeeds. All signal handlers are read before selected handler installation begins, so partial installation has known restoration targets.

Selected live/release/final JSON writes use the actual owned-IO exclusive writer and independent descriptor cleanup; legacy `_atomic` is unchanged for old callers. Partial and failed files remain present. No failed temporary publication is silently removed or retried. A selected ordinary body failure without cleanup uncertainty still returns a failed state, preserving the pre-existing guard interface. Actual fatal or cleanup uncertainty, changed first-fatal selection or any finalization failure raises the selected original exception after independent cleanup attempts.

The final state is failed after any error. A late final-receipt close/fsync or directory-sync failure can occur after a complete-looking immutable `final.json` body was physically written. That original body is preserved; the invocation fails, attempts failed live publication and a distinct exclusive `native-finalization-failed.json`, and never returns success. The outer caller must reject a failure marker or failed invocation and must not infer success from an isolated final body. Failure-marker writing itself may fail; the preserved raised failure remains authoritative. This is qualified evidence, not a claim that disk writes are atomic across the complete cleanup sequence.
