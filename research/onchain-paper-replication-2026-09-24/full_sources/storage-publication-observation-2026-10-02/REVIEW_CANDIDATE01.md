# Independent bounded-rescan candidate01 review

Acceptance is withheld for the three narrow implementation/evidence findings below. The bounded-rescan design remains supportable under its stated sampled semantics; no relaxation of accepted-scan hardlink checks or broader scientific work is required. Review inspected source and raw logs only; it ran no tests, imports, jobs or empirical work and made no production changes.

Candidate manifest SHA256 is `4032113332cf328ad3f3c5a2d064a70d67859b37850052854cdf86fcec3e768e`. All five referenced file hashes/sizes matched, and baseline.py is byte-identical to the target at e0cb08b6bf763ffec0bb4058d5d1d89bd3977486. The twelve retained passing small checks are real evidence for their covered cases, not complete coverage of the stated deadline/cleanup/diagnostic claims.

1. **SW1 — accepted elapsed time excludes final descriptor cleanup.** Candidate lines129–134 construct the accepted result and elapsed_seconds before root `_close` executes; check lines67–81 then accept that result without a fresh deadline check. A deterministic clock advanced beyond the common budget by a successful final close would still yield acceptance and a stale elapsed value. Also line75 sleeps the full five milliseconds even if less time remains. Compute/check total elapsed after all attempt cleanup, and refuse acceptance or another full wait if the shared budget has elapsed. Keep the existing qualification that Python cannot preempt an uninterruptible metadata syscall. Add a fake-clock successful-close-overrun check and a near-deadline backoff check; the current wait test only observes an overrun on the next loop entry.

2. **SW2 — incomplete first-fatal and iterator-cleanup handling.** `_close` lines39–46 preserves an existing fatal primary, but if close itself raises the first MemoryError/KeyboardInterrupt/SystemExit it instead raises a new StorageCleanupFailure, losing the original fatal identity and, when no primary exists, its causal object. Separately, `with os.scandir(fd)` at line103 still allows iterator exit failure to replace an earlier traversal fatal before the enclosing root/child handler can retain it. The new behavior explicitly claims fatal/cleanup preservation, but tests90–95 cover only fatal fstat followed by os.close failure. Retain a first fatal cleanup object, chain a prior ordinary body error when appropriate, and handle iterator cleanup using the same priority discipline. All independent owned-descriptor cleanup must still be attempted, without retry after any uncertain cleanup. Add sentinel tests for first fatal os.close, ordinary body plus fatal close, nested body fatal plus iterator-exit ordinary failure, and iterator cleanup followed by root-descriptor cleanup.

3. **SW3 — retry history and partial counts are not retained by the actual guard failure path.** HardlinkObservation lines26–34 stores one path/stat and `.history`, but no `.observation` with partial accounting. The final persistent-link branch adds previous paths only as exception notes. Actual resources.observe_storage persists `str(error)` and, only if present, `.observation`; its outer guard also stores the exception type/text, not notes. Thus persistent failure preserves only the last path and loses previous observations/counts. If a retry instead fails on root replacement, quota or another non-link error, check propagates it without attaching the already observed hardlink history at all. Attach a bounded serializable observation containing original per-attempt path/stat/partial counts and retry/elapsed metadata to every relevant terminal storage failure, in a form the existing guard actually retains. Preserve equivalent bounded history on success. Add checks against the guard's real serialization contract, including persistent-link and link-then-nonlink failures. An in-memory `.history` assertion alone is insufficient evidence preservation.

## Quota and sampled-policy assessment

The existing per-entry enforce calls raise StorageLimit immediately; check catches only HardlinkObservation. Therefore a quota violation already detected before encountering a hardlink is not discarded or retried. Each retry initializes new totals, and a persistent byte violation encountered by its complete traversal will still fail. This part of the design is sound.

The partial scan stops at the first linked entry before accounting that file or scanning subsequent entries. Bytes beyond that point are not measured by that partial scan. A file can grow and shrink between discarded attempts and the final scan, just as between ordinary periodic scans. Acceptance must therefore claim only the fresh complete sampled observation, never absence of a historical/transient byte breach. Explicitly test both a deterministically ordered quota-before-link refusal and a byte breach introduced/retained before the next full scan. Do not retry StorageLimit or merge partial accounting into the accepted result. If a linked file's own size is not classified as a byte violation before retry, document that no byte observation for that entry was accepted; do not claim its discarded stat was an all-clear measurement.

At most three attempts is finite even with a stationary clock. The manifest explicitly allows up to three times the per-scan entry budget; this is a changed traversal-work allowance and must remain documented. All accepted files must still be singly linked, same-filesystem, ordinary, and under the original anchored root. Persistent links, namespace/root replacement and other non-link errors remain terminal. This policy is not an atomic snapshot, filesystem quota or guarantee against growth during blocked metadata calls.

Preserve candidate01, baseline and failed/passing logs. A corrected frozen candidate and the requested focused deterministic evidence can be independently reviewed before integration. No historical owner attempt should be rerun to fix these engineering findings.
