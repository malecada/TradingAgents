## Failure semantics: explicit reason this is not yet integration-ready

The existing reviewed grouped API performs all role-integrity checks and final
fresh admission/rejoin before returning any body. Therefore, if an early graph
has malformed semantic metadata and a later graph has an integrity failure,
the selected bundle raises the later integrity failure before parsing the early
graph. The legacy route reports the earlier semantic failure. This unavoidable
transaction-order difference is captured by a focused fixture; it is not hidden
as exact failure-prefix parity. A source mutation at bundle exit likewise
refuses before semantic processing, as the existing grouped API requires.

The candidate preserves the exact primary exception from a failing bundle,
does not retry/fallback to stale bodies, and performs no publication before
validation. Absent policy preserves legacy ordering. Pure semantic failures
with valid registered bodies retain the existing semantic validation order.
Nevertheless, **strict unchanged mixed-failure precedence is not satisfied by
the selected candidate**. If that requirement is non-negotiable, this candidate
must remain uninstalled; it cannot be called complete under that criterion.
A caller flag alone is not authority to waive the requirement. Root must make
this selection/cadence disposition concrete in the combined changed-seam review.

## Higher-impact next seam for Root

Five role admissions are not the main1129-second opportunity. The exact larger
seam is the three full checks inside one selected `Target.check`, repeated five
times in `_prepare`. At minimum, one private compound boundary would have to
retain fresh source/claim/input/runtime checks at entry and exit, retain every
intervening live Owner/guard/provenance/graph check, and perform callback-free
final byte/object rejoins. Reducing full checks across those callbacks changes
mutation-detection timing and first-error precedence; the current `read_inputs`
API only brackets role reads and cannot certify that compound operation.

This investigation deliberately does not invent a cross-admission success cache,
assume writer exclusion, suppress existing callbacks, or implement a broad new
authority framework. The next Root choice is to review that **specific existing
Target.check compound seam** with its actual callback/mutation threats, or retain
its checks and optimize the underlying fresh admission work. Repeatedly optimizing
the0.275-second compile phase cannot materially address the measured bottleneck.
No new native run, source release, financial registration or capacity grant is
created by these source-fixture results.
