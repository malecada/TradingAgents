## Subsequent canonical-schema finding

**ASC3 — Python object equality does not preserve the exact serialized schema.** The initial `check.inspect` compares reconstructed `got` to parsed `result` using dictionary equality. Python treats an integral float as equal to the corresponding integer, and booleans can equal zero/one. A caller-rehashed completion changing only integer `completed_pairs` to a float therefore need not refuse, despite differing from the canonical result produced by verification. Compare canonical reconstructed result bytes directly with the trusted raw completion; use exact canonical comparisons for the retained event-read completion and cross-proof replay summary as well. This is an exact schema/identity consistency issue in explicitly supplied malformed proofs, not an attack that preserves the original expected hash. The fresh targeted regression was still running when this finding was added; no test result is inferred here.
