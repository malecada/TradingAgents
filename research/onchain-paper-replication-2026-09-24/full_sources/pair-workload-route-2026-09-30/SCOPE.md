# Registered workload and resident-graph admission component

This isolated read-only component joins actual ResearchRun and matching-owner
admission to a versioned, registered workload control. Both the selected job and
producer plan must name that control; its hash is part of the representation
descriptor and therefore the workflow identity. The imported route source must
be registered byte-for-byte. Owner, runtime and numerical source checks use the
maintained matching-owner implementation.

Control admits the checkpoint operation/publication schedule, dictionary matrix
entry bound, logical journal limits and SHA256 of the complete ExampleManifest.
The latter includes ordered train/test rows, labels, masks, source/fold hashes
and exclusions. This is an immutable input binding, not an outcome evaluation.
The existing registered graph manifests must cover exactly the actual graph
population; real GraphSnapshot identities, configuration, seed and fold rebuild
the descriptor. Example clocks and graph availability are checked. Wrong control
routes and invalid scalar limits fail before iterating actual graph inputs.

The sample check verifies the exact eligible training graph population, count,
seed, configuration/order identity and distinct centers. It reconstructs induced
neighborhoods from actual admitted parents and compares typed graph identities,
including attributes and topology. Sample arrays are therefore not accepted
merely because the older sample identity covers their accompanying metadata.
The derived dictionary workload hash is checked against a purpose generated by
the existing accepted workload implementation.

Initial review withheld acceptance for two reproduced failures: a changed test
population could preserve the required graph union, and hash-only lease checks
did not reject a new metadata hard link. Full ExampleManifest binding and the
existing bounded same-device/single-link metadata reader address these findings.
Original source/tests, initial passing log, withheld review and failing regression
log remain preserved. Corrected check02 passed all 13 cases in 74.146 seconds,
exit zero. No broad-suite or empirical verification is inferred from this log.

## Explicit limits

- No journal, pair directory, sample draw, model fit or empirical run is launched.
  This is one admission component, not the complete production execution path.
- Tests use actual temporary registrations, committed source, ResearchRun and
  Binding; the kernel guard observation is mocked. No supervisor death or
  empirical resource enforcement is established by these tests.
- Resident GraphSnapshot inputs are required. Mapped graph population ownership,
  streaming full-fold admission and same-run published graph outputs remain
  separate work. This restriction must not become a reduced empirical scope.
- Reconstructing the sampled induced graphs does not independently replay the
  weighted RNG sequence or prove recorded draw probabilities. The actual sampler
  and its published output provenance remain mandatory in the producer.
- Pair-journal owner/failed-ancestor joins, MCM/dictionary artifact routing,
  physical whole-workflow quota, orphan reconciliation, scalable journal/lease
  checking and complete representation reuse remain outstanding.
- A route lease rechecks admitted compact metadata and live owner state; it is
  not a replacement for full source/runtime checks and the outer source freeze.
- The actual example identity is bound, but the complete raw-price/calendar
  reconstruction and registered expected-date denominator still need their
  independent data admission. These tests do not establish paper coverage.

No maintained package source, empirical protocol, historical result or budget
was changed. Direct dependency hashes will record component provenance, not a
complete empirical execution closure. All 1420 financial fits remain pending.
