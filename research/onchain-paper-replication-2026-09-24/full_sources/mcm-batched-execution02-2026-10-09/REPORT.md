## Binary format and consumer

Record is genuinely `Struct('>Q32sdIB')`, exactly53 bytes: ordinal uint64,32-byte fresh purpose SHA256, binary float64 score, iterations uint32, status uint8 (0 temperature_complete;1 iteration_cap). No per-cell JSON/hex string/file is emitted. Header `>8sIQQ32s` is60 bytes: MCMBAT02 magic, record_size53, start, stop and pending SHA256. Pending JSON binds contiguous range and SHA256 of ordered concatenated32-byte purpose digests; pending alone marks every cell attempted/unknown. Complete JSON binds pending SHA, payload SHA, exact payload extent and record width. Three final files per batch: pending.json, records.bin, complete.json.

Each temporary is exclusive O_NOFOLLOW, regular mode0600, singly linked, extent bounded, fsynced and exactly read back/hashed with descriptor/path signatures before/after read. Publication uses exclusive hardlink: both names must refer to pinned inode with linkcount2; after fsync/unlink temporary, final must have linkcount1. Final metadata marker is published last. Before credit, read_complete verifies root, pending schema/range, complete commitment, exact header/extent, ordinal sequence, finite[0,1] float64, status tags and ordered purpose aggregate, then rejoins all file bytes/inodes. Caller invokes read_complete(batch_index) for validated tuples `(ordinal,purpose_digest_bytes,score,iterations,status_code)`; a raw binary filename or old score-stream receipt is not completion evidence. Consumer refusal poisons too.

Limits: batch<=4096, max_cells<2**64, bounded encoded purpose<=8192B, metadata body1024..1MiB, payload exactly60+53N, cumulative bytes charged on attempted writes and pre-reserved metadata+payload space. Caller metadata/graph objects and JSON encoding input allocations remain outside encoded-body accounting. Namespace creation is exclusive. One writer/trusted parent is assumed; supplied callbacks mutating the inspected files/path are tested, but this is repeated currentness checking rather than global atomic writer exclusion. Arbitrary internal-object rewrites, hostile parallel writer races and power-loss certification are not claimed. Failed post-publication cleanup may leave a closure-valid committed chunk despite an exception; use the verified consumer, never method-return inference alone. No automatic resume/retry/deletion or external authority is added.
