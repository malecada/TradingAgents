# Synthetic matching workspace and checkpoint probe

One prospective engineering resource measurement, using only newly constructed
constant-feature, zero-edge 2,000-by-2,000 graph pairs. Exactly 4,000,000 pair
entries equals the current unchanged scientific capacity. This is not a financial
experiment, source transformation, sampled real graph, or additional family claim.
No existing raw, array, ledger, price or remote body is read. Frozen production
source and active storage04's 63 bindings/HEAD remain unchanged.

Run the accepted composite checkpoint prototype with three float64 matrices,
128 MiB retained-state and logical-checkpoint allowances, 65,536-entry chunks and
8 MiB hardening scratch. Explicitly limit the synthetic configuration to two
annealing iterations; this is a measured prefix, not the paper's full schedule.
Then run exactly 256 hardening chunks, preserving an incomplete checkpoint.
Measure creation, annealing, hardening-prefix, save and restore separately. Delete
only the in-memory prior state before restore. Retain all on-disk partials and the
checkpoint, including on failure; never overwrite or retry this identity.

Check the fixture's uniform soft matrix against 1/2000 with absolute error below
1e-14, selected row-major tie pairs against the diagonal prefix, and restored
matrix bytes/cursor/pairs against their saved identities. These are fixture
invariants, not independent full scalar-oracle parity or a universal precision
proof. Saved checkpoint files are synthetic artifacts, not study observations.

Guard: 1 GiB maximum, 768 MiB high, zero swap, two CPUs, 3 GiB host reserve,
4 GiB startup available, 10 GiB free disk floor and 180 seconds. Require at least
10 GiB plus 256 MiB free at dispatch for retained checkpoint/metadata. It may run
alongside the existing separately owned storage04 only after verifying exact
storage owner and source freeze, sufficient fresh host memory/disk, and no other
conflicting empirical job. Independent scope/source/limit review precedes execution.
The hard memory ceilings total 1.25 GiB for these two jobs; this is a limit sum,
not a guarantee of aggregate host usage or a speed estimate.

This profile includes validation and hashing overhead but excludes completion of
all greedy hardening iterations, final scoring, nonzero edge cross-products,
large real neighborhoods, dictionary/MCM/neural execution and GPU work. Its peak
and timings cannot be projected to those omitted costs without further reviewed
measurement. A resource-limit failure is retained as evidence, not bypassed by
loosening the limits. No production integration or empirical release follows.
