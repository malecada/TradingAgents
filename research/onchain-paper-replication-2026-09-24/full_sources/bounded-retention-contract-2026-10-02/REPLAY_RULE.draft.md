# Proposed replay rule v1 — outcome-independent first/last

Status: unadopted; independent reviewer approval and executable resource/input
limits are still required. The rule narrows the previous wholly unresolved
selection choice; it does not claim maximal-shape empirical coverage.

## Common selection

Before numerical work begins in each predeclared dictionary/MCM stage, freeze its
scientific input population, ordered comparison schedule where knowable, exact
selector identities and this rule hash. Select the first and last **distinct
ordered pair identities** in that schedule; deduplicate when only one exists.
An exact empty stage has an explicit empty selection, not a guessed last ordinal.
Capacity reservations are never an observed or exact stage denominator.

For each selected comparison retain the first checkpoint at the unchanged safe
cadence if one occurs. If completion precedes that checkpoint, retain an explicit
`completed_before_first_scheduled_checkpoint` disposition. Do not force an extra
snapshot, delay completion, alter cadence or replace a member that fails. A
selected failed/unavailable comparison retains that disposition and any surviving
first scheduled checkpoint; it is never replaced by a successful or cheaper one.

Retain exact input neighborhood bytes, ordered direction, graph/node/sample/motif
identities, matching config, source/runtime/RNG bindings, the ordered completed
score/convergence/iteration record where available, and required body/manifests
for bounded from-start independent replay. Bodies and replay cost need positive
reviewed limits; an oversized selected member is an admission blocker or explicit
unavailable cell, not permission to substitute another. Hash-only input records
cannot satisfy this replay body's availability requirement.

This rule does not choose on score, accuracy, convergence success, wall time or
retention cost. Resolving an already selected identifier to its actual immutable
purpose hash does not permit changing membership.

## MCM stage

Freeze Nnodes, Kordered motifs, graph/node ordering and dictionary identity before
the stage. The exact schedule is center-major then motif-major, denominatorN×K.
For N×K≥2 select ordinals0andN×K−1, namely(center0,motif0)and(centerN−1,motifK−1).
For N×K=1 select ordinal0once. Full exact neighborhoods and motif inputs must be
retained for replay. No capacity upper bound is used asNorK, and no uncompleted
last member is replaced by the last successful member.

## Dictionary stage: exact single-block resource configuration

The existing original512-sample configuration is below partition_threshold2048.
The preserved workload.distances iterates i=0..n−1,j=0..i−1, then directions
(i,j)and(j,i). No reused earlier matrix exists at its initial single block.
Exact numerical comparison denominator is therefore n(n−1)=261,632 for n512;
select ordinal0:(sample1,sample0), and ordinal261,631:(sample510,sample511).
Sample ordering, complete sampled graph bytes and the exact dictionary/matching
configuration are frozen before matching; selected membership is score-independent.

This is a claim about the actual single-block configuration, not a rule equating
compact_policy.dictionary_capacity.max_pairs with actual occurrences universally.
The stage's completion count must still independently join its actual event ledger
and frozen sample/matrix population.

## Dictionary fallback when realized schedule is adaptive

The preserved workload.reduce can cluster seeded initial partitions, then choose
medoids and recurse; distances reuses a matrix for an identical ordered subset.
Thus actual later block membership and distinct numerical comparison count can
depend on earlier distances. It is incorrect to identify the last comparison by
subtracting one from max_pairs or by discovering a favorable completed count.

If exact stage numerical occurrence schedule cannot be bound before outcomes,
freeze a selector population of **initial eligible sample ordered-pair identifiers**
before stage work: derive the initial partition subsets using the same immutable
sample ordering, unchangedPCG64seed and partition configuration; enumerate each
initial block's i/j directional comparisons in deterministic block/loop order.
Select the first and last distinct(left_sample_id,right_sample_id)identifiers in
that enumeration, with their initial block ordinal/subset hash. Retain a selected
member's first scheduled checkpoint on its first actual numerical occurrence.

These are explicitly initial-eligible-population endpoints, not claimed endpoints
of the adaptive whole-stage completion count. Their membership is fixed before
numeric outcomes. Actual purpose hashes include block/hierarchy provenance and
must be joined when observed without changing the preselected pair identifiers.
If a selected call is absent or a verified reuse supplies its score, record that
exact reason and source-score lineage; do not invent a new comparison or alter
reuse merely to produce a checkpoint. Any required from-start replay remains a
separately registered validation operation with full selected inputs.

The full sample population, deterministic reduction/reuse protocol and selector
population must be frozen before stage work. The realized adaptive event count
remains an output verified against complete algorithm/matrix provenance; it is not
retroactively called a preknown denominator. If admission insists on a preknown
exact numerical-call count for such a configuration, the configuration stays
blocked until that separate contract issue is resolved. This draft does not relax
that gate or redesign dictionary science to make the count convenient.

## Coverage limits and independent checks

First/last empirical endpoint selection does not guarantee largest-shape,
annealing/hardening boundary, tie, zero-edge or worst-case resource coverage.
Those cases remain required in an independently frozen **synthetic** fixture set
(BR01–BR03), with reference expected answers independent of the retention code.
No additional maximum-shape empirical member is selected by this version.
The replay report must distinguish empirical endpoints, synthetic shape/phase
coverage, numeric recomputation and integrity-only checks. The original neural
saved-checkpoint/metric replay obligations C13/C14 remain separate and unchanged.

Across retention variants, compare exact numerical array bytes/hash and semantic
scientific identities (input sample/graph/motif membership, ordered direction,
matching config, seed/RNG and completed numerical results). Source commits,
retention-policy hashes, operational workload/owner/receipt identities and encoded
manifest/output-file hashes may legitimately differ because the new variant has
new provenance. Expected metadata differences must be explicit; they are not a
reason to permit different numerical bytes or scientific populations.
