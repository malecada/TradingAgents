# Finite historical-source / comparison registration evolution

This source protocol creates no registration, execution permission, capsule, commit or claim. All six selected proof tools, the complete 195-source closure, locked runtime and original materialization inputs must be installed and committed before materialization at source **A**. The two existing identities and total attempt budget2 are unchanged. A closed phase cannot be rerun.

1. Root admits and executes the genuine materialization once at A. Its actual ResearchRun, native controls, original claim/source/Owner, complete43 emitted inputs, original raw output, controller/supervisor observations, wait/absence and tail evidence must pass independently.
2. Before drafting comparison, a source-pinned caller invokes `authenticated_materialization(root, accepted_ref, wait_ref)`. This read-only helper authenticates all original evidence at A; current HEAD may equal A or have A as its sole direct parent. It never invokes admission or creates a claim. It returns `context`, `observed`, `material`, and the original committed `registration`. The `material.inputs` set has exactly43 names. Hash references are the existing exact `proof_raw01.ref` format, with kind/document bounds; labels or caller-created receipt fields confer no authority.
3. The comparison registration uses a fresh path, preserves all registration top-level fields other than adding exactly the comparison experiment, preserves the original experiment verbatim, and preserves family/history/datasets. The comparison parent is the materialization identity; all unchanged experiment fields (including stage/reuse/windows/runtime hashes/source files) remain equal. The only permitted changed experiment fields are parent/question/cells/outputs/inputs/charter. Inputs are the43 actual emitted refs with `future_execution_job` renamed `execution_job`, plus the identical original environment ref. No data, policy, training, source or hash substitution is permitted.
4. The comparison charter template can exist at A, but its registration-referenced charter must be installed at a fresh path in B. Materialization registration/charter/history remain unchanged. Create a new typed evolution document containing exactly schema_version1, kind `cold-proof-additive-registration-evolution-v1`, parent_source A, original_registration ref, current_registration ref, accepted ref, wait ref, and additions.
5. `additions` is a sorted unique list of 2–47 `{path,sha256,role}` rows. New comparison registration and charter are mandatory. Optional entries are exact emitted-input refs, the comparison phase contract and the otherwise identical source-document metadata. Permitted role strings are `comparison-registration`, `comparison-charter`, `emitted-input`, `comparison-phase-contract`, `unchanged-source-document`. No runtime update, arbitrary metadata, old-file modification/deletion/rename or numerical source change is admitted. Emitted raw array bodies remain separately authenticated by the original materialization parser and need not become Git additions; their existing hashes cannot change.
6. Commit **B with exactly one parent A**. Its exact Git diff must be only the declared additions plus the evolution document itself. The own evolution-document path is deliberately excluded from its own hash list; its bytes are authenticated by the actual B Git blob and the external reviewed comparison release reference. The evolution document must not contain B's commit identifier or its own hash. The comparison registration must not register the evolution document as an input. Thus no self-hash, self-commit or mutual registration/evolution hash cycle is required.
7. After B exists, create/review the comparison release envelope outside B's committed additions. It names actual source B, the committed comparison registration and a prior_materialization object containing exactly accepted/wait/evolution refs. Runtime and native-environment refs and CPU selection are exactly the originals. Source documents may have different paths but their full195 maps must be equal. Release/phase metadata retains existing compact/document bounds; the typed evolution is a document, not an inline compact receipt.
8. Final `authenticate_prior(root,current,experiment,job)` independently revalidates original materialization evidence at A, then validates B's exact parent, complete finite diff, every Git/body/ref hash, conserved registration/history/runtime/source and comparison inputs. No cached success summary replaces the raw chain. Fresh launch admission still checks current HEAD and refuses existing comparison namespaces.

Only root may compose/freeze/review/adopt the actual capsule and registrations or launch numerical phases. All previous failed/refused attempts remain immutable. Actual OS, numerical lifetime, object sharing, gradients, Adam/checkpoint equivalence and capacity proofs remain pending. This preparation neither replays original512 sampling nor constitutes original-paper/financial-fit completion.
