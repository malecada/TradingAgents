# Exact numeric-result reuse — engineering candidate only

`numeric_reuse.py` wraps the accepted PairExecutor without changing its implementation. This is a new operational contract: a successful exact cache hit skips repeated numerical advances and checkpoint callbacks. It is not an assertion that every occurrence executed the original trace, and it grants no old pair-log or representation-complete authority.

Every call validates the fresh purpose, original pair/graph/configuration/policy, and public graph identity. Reuse requires exact ordinary AttributedGraph objects with ordinary identity strings and contiguous ordinary numeric arrays backed through a bounded readonly ndarray chain by immutable bytes. Unsupported mutable/subclass graphs still run the original executor and are never cached. Oversized exact keys likewise compute without caching.

The key contains the exact matching configuration plus BOTH ordered graphs' node_features, edge_index and edge_features dtype strings, shapes and raw bytes, with length-delimited framing. It contains no node IDs, center IDs or parent identity; those are nevertheless validated on every occurrence. Equality is actual bytes equality, not digest equality. Signed zero, row/edge order, numeric dtype and configuration are not normalized. Only a finished score/iterations/convergence tuple is admitted to the cache. An error, unfinished checkpoint stop, runtime change or failed post-callback input rejoin poisons the wrapper and clears its entries.

The module loads the exact accepted executor SHA6d1ad3a7. SOURCE_PINS.json pins nine source bodies. Every occurrence checks current source hashes, the trusted-import function/code roster, selected direct NumPy/math functions, default floating-point rounding/error modes, configuration/policy/schedule and checkpoint-callback identity. Checks repeat after computation, before caching or returning a hit. Immutable exact numeric bytes are rejoined after checkpoint callbacks. These guards assume the initial import came from the trusted reviewed runtime and exclusive graph/state ownership. They are not an independent proof against hostile monkeypatches installed before import, arbitrary transitive native-library/global mutation, direct tampering with private cache state, or concurrent writes. No externally supplied expected-code cache or runtime token is accepted.

## Memory and lifetime

The LRU uses a fixed-length slot list, capped at4096 entries, not a resizing hash table. Admission accounts for the actual `sys.getsizeof` slot list, entry tuple, exact key bytes, result/origin tuple and all retained primitive values (shared values are conservatively charged per entry). Eviction happens before a new entry is retained. A hard configurable cache-object ceiling is at most64MiB; an exact key is at most8MiB and no larger than that ceiling. An empty slot table that exceeds the requested allowance is refused. Oversized entries are not retained. No cached key or result retains a graph object.

This is a bound on retained cache object allocation reported by this CPython runtime, not allocator arenas or process RSS. Exact-key construction has separately bounded transient storage: framed array byte copies and their joined key, and a second key during post-callback comparison, each bounded by max_key_bytes. Python part/header objects, immutable source/config/runtime guards, one last occurrence receipt, caller callback references, original numerical state and allocator overhead are additional. The process resource guard remains necessary. A previous OrderedDict-copy implementation and its initial test output are preserved as `numeric_reuse_pre_fixed_slots.py`; it is not the final candidate.

## Fresh occurrence evidence

Every successful call returns the original numeric triple and publishes only one bounded `last_receipt`: new occurrence ordinal and purpose hash, computed/reused mode, originating computation ordinal/purpose, exact f64 score bits, iterations/convergence, and actual checkpoint-count/byte deltas. Hits have zero new checkpoint reservations. Counters distinguish computed and reused occurrences. The receipt explicitly denies old per-occurrence execution credit. The caller must synchronously preserve this receipt with its own fresh coverage record before the next call overwrites it. There is no durable provenance publisher, original score-stream adapter, admission, Owner, restoration or empirical integration in this module. Repeated caller-supplied purpose hashes do not independently prove fresh scientific coverage; the wrapper's local monotonically increasing ordinal is engineering evidence only. `close()` clears entries/receipt and refuses further use.

## Tiny actual-engine checks

Final TEST03 and SUPPLEMENT03 pass using pinned Python, CPUs3/4, nice10,30s,256MiB AS,4MiB FSIZE and single-thread settings. Checks include different node/parent IDs with identical numeric bytes reusing exactly; fresh occurrence/origin provenance and zero hit-checkpoint charge; original reference agreement within1e-12; node/edge-feature/edge-order/dtype/signed-zero/right-graph differences computing again; one-entry LRU eviction; mutable backing and oversized-key fallback; configuration/runtime/source mismatch refusal; purpose-subclass refusal; poisoned/unfinished results never cached; and actual engine state cleanup following a checkpoint exception. The cache does not alter output f32 conversion because no conversion occurs here.

No benchmark, empirical hit rate, population speedup, original graph payload, test label, registration, budget, Main source or live process was used or changed. Independent different-author review remains required. Exact-key construction and repeated source/identity checks have real costs; usefulness is not established by tiny equality checks.
