# Conditional checkpoint contribution accepted

The candidate manifest and all 15 source/policy pins match actual bytes. Independent integer arithmetic and AST inspection pass (CHECK01.log). The four original synthetic control-flow tests are reused rather than rerun. No snapshot or scientific array was created.

PairExecutor.__call__ executes exactly one selected outer checkpoint iteration, returns completed scores before publication, and otherwise calls the snapshot callback once followed by CheckpointStop. Its exception path poisons the executor and preserves the primary while attempting both cleanups. The reuse/execution wrappers, journal/driver and compact producer propagate failure rather than continuing. The actual real_pilot_import_caller graph loop has no catch/continue; its enclosing handler preserves the failure and rethrows after terminal publication. Training follows successful completion of that loop only. Therefore completed earlier pairs/graphs cannot have left matching snapshots; the first attempted snapshot is terminal, including failed save or cleanup.

The callback forwards the actual pair max_checkpoint_bytes and checkpoint_layout to matching_checkpoint.save. The sharded save checks 4*A+3*65536 before mkdir. checkpoint_chunks writes exclusive final shard paths directly, with capped manifests and no second disk copy or retry. Partial saves are a prefix of that same file set. This conclusion assumes ordinary pinned NumPy serialization of the flat float64/int64 chunks, including the 128-byte header, not arbitrary replaced runtime code. The callback sidecar is created after snapshot manifest readback, capped by the ordinary 8192-byte writer. Training's separate writer checks its 4MiB cap before writes.

For N=8,402,640 and chunk_entries=262144, A=67,225,344 bytes over 33 shards; four arrays plus three manifests total 269,097,984 bytes. Including one sidecar gives 269,106,176 bytes in at most 136 files and three snapshot directories. Independent per-file 4096-byte rounding plus three 4096-byte directory contributions gives 269,635,584 bytes. Adding an 8192-byte failed receipt and a conservative separate 4MiB training snapshot gives 273,838,080 bytes. Matching fatal snapshot and completed training are mutually exclusive, so summing both is conservative. Seven graph checkpoint parent directories remain separately accounted.

This is a conditional contribution, not measured filesystem occupancy or whole-job capacity. Inode/allocator metadata, other directories, other outputs, partial transfer stores, source-context records and runtime memory remain outside it. In-process checkpoint scratch is not a second disk copy. The original logical reservation of 160*(269,097,984+2*8192)=43,058,298,880 bytes and pair allowance remain unchanged.
