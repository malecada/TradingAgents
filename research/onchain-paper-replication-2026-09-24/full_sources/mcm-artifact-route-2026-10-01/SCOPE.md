# Current-owner saved MCM reuse with an issued prerequisite

This component separates actual dictionary preparation from saved-MCM reuse.
prepare_dictionary calls the immutable predecessor's full admission once, which
may reconstruct sampled neighborhood membership and load sample/dictionary data.
It issues a module-local weak-key ticket after binding the exact current owner,
feature journal, source files, preparation input names/hashes and actual admitted
dictionary receipt. Dictionary, record, callback and class lease function are
pinned and checked before/after the original lease. Replaced prerequisites,
cross-owner/journal tickets and unissued constructors refuse. This is an
in-process contract, not a Python security boundary. Cold-start, historical,
sealed and mapped admission remain separate.

The saved MCM call requires that ticket. It joins exact required graph and node/
motif order, dictionary identity/configuration/provenance, matching workload,
selected output/execution/read policies, completion/start proof, source set and
event/component bindings. Full row/cell, numeric and encoded-byte claims are
required. Conflicting sidecars, unknown file inventory and duplicate MCM events
refuse. Prior embedding/completion of another graph does not block the selected
graph. Strict native float32 component inspection occurs before matrix loading.
No initial dictionary admission, sampling, fitting, matching, Serial, PairSession
or neighborhood reconstruction occurs during saved reuse.

The selected read policy reserves two full numeric payloads (reader storage and
an immutable bytes-backed copy) plus conservative validation scratch: one float32
chunk and one boolean chunk, five bytes per entry. Chunk size is at most65536.
Values must be finite and in[0,1]; zero remains legitimate. The raw reader matrix
is released before final admission. Returned receipt properties are nonassignable;
its storage cannot be made writable, including through its base/view. A lease
also checks shape, strides, dtype and writeability before/after evidence checks.
Saved metadata, component, graph and prerequisite leases remain attached.

Parent graphs, issued tickets and retained sample/dictionary data, metadata and
process RSS remain outside this read allowance. The evidence is not whole-workflow
or measured resource admission. Tickets must already have passed their distinct
preparation step; these results do not establish cold-start or historical reuse.
