### OIS2 — The new import path still loses inner descriptor ownership and first-fatal identity

Locations: `original_import_stage.py:17–22,61–67`; candidate `compact_owner.py:48–63,96–113,190–201`; actual inherited `tradingagents/research/onchain_replication/score_batches.py:28–52,100–110,127–147`.

The accepted original `_close_owned` reducer protects the outer stage directory descriptor only. Stage publication calls `io._write`, which opens a child descriptor and then enters `with os.fdopen(child, 'wb')`. If fdopen construction fails, there is no owned-child cleanup. If writing/fsync raises a fatal and stream closing raises an ordinary error, the context-manager error can replace the fatal before the outer reducer receives it. Thus a fatal-safe outer finally does not establish a fatal-safe publication chain.

ImportStage integrity also calls `owners.exact`, which uses the inherited `_read` and `_release` chain. `_cleanup` constructs a new CleanupFailure for collected close exceptions and `_close_after_failure` may replace an already active actual fatal with that wrapper. The inherited held-token release and Owner constructor have analogous uncorrected boundaries. The implementation report acknowledges these limitations; they are real source-level gaps rather than successful failure-path evidence.

Before durable import execution is accepted, correct the newly reachable ownership chain under explicitly assigned source ownership: retain descriptors immediately after successful open; independently close each exactly once; attempt required independent cleanup; select the first actual fatal before wrapping ordinary uncertain-cleanup errors; retain earlier ordinary and existing cause information. Include sentinels at child fdopen/write/fsync/stream-close/child-close/parent-close and token release, with body fatal, later fatal and ordinary-only combinations. Partial namespaces/bytes must remain, owner failure must remain terminal, and uncertain descriptors must never be retried. A generic source-presence assertion cannot verify this. This finding does not authorize a broad unrelated refactor or changes to historical candidate bytes.
