## One bounded implementation seam

A candidate can avoid retransferring/re-hashing identical immutable Git blobs **within one Binding.check only**, between `ResearchRun._check_source`/`admit._source_files` and `matching_owner._source`. Admission already resolves and authenticates source/design Git blob extents in bounded batches. The later numerical-anchor check currently obtains all193 anchor bodies again. A private invocation-local table of already verified `(Git object ID, size, SHA256)` could let that later check freshly resolve each numerical-anchor path to its actual object ID/size, compare it to the previously verified extent and expected digest, and fetch/hash only misses. Retain the current late local-source byte hashes, complete required-source roster, numerical commit/path mapping, runtime inventory, input hashes and final Owner/native/claim checks. Do not use pathname/mtime/SHA declarations alone as proof, and do not skip fresh anchor resolution.

This proposes content verification reuse, not reuse of an authority decision: retain both entry/final admissions and all intervening callbacks. The table is bounded to already authenticated roster/extents, discarded on return/failure, never carried across intervals or callbacks as a grant; Git-object immutability remains the same repository trust assumption used by existing checks. It needs a separate concrete implementation and review, including malformed/missing objects and failure cleanup. No implementation or speed saving is established here. Consolidating the two admissions across Prepared's callbacks is **not** justified by this investigation because those callbacks can change current evidence.
