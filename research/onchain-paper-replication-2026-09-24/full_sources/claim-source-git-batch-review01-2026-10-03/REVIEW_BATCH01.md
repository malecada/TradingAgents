## Cleanup and enforceable bounds

The selector loop is single-threaded; no pump thread is created or left to join. The child’s stdin ownership is marked before close, avoiding a retry of uncertain close. Stdout, stderr and selector each have an independent final cleanup action. Stop and reap are independent, so a stop failure cannot silently bypass the reap attempt. Cleanup that cannot be established raises synthetic uncertainty, never success. A first actual fatal outranks ordinary errors and that synthetic wrapper with object identity preserved. Secondary annotations are deliberately omitted; arbitrary exception formatting is not introduced. A failed bounded wait can still leave cleanup uncertain, which must remain a failing verification and be contained by the actual outer process/unit policy.

The accepted change is explicitly stricter than the old unbounded check_output route: at most128 requests and64KiB request bytes, at most8MiB per blob, and at most8MiB+16KiB total child stdout including framing, with64KiB stderr. This is the implemented total-output ceiling, not a separate exact8MiB sum-of-bodies quota. A group whose output exceeds it refuses rather than silently dropping/splitting already acquired evidence. Fallback expression bytes are capped at128KiB and remain subject to OS argv limits. Full child output is buffered and converted to immutable bytes, so bounded duplicate temporary storage is possible. This is not an empirical RAM measurement.

The10-second monotonic budget bounds the monitored transport/wait route and a separate cleanup wait is bounded at five seconds. Popen/OS scheduling and the other unchanged _blob calls are not converted into a hard whole-verify_claim deadline. The actual outer native/resource limits remain necessary. A transport timeout/output cap/nonzero exit for a group can precede an earlier buffered semantic hash mismatch. Once transport succeeds, parsed body/hash order is preserved, and earlier queued comparisons precede later ordinary path validation failure. This deliberate transport-error priority and differing stderr observations are accepted as fail-closed engineering behavior, not identical exception timing.
