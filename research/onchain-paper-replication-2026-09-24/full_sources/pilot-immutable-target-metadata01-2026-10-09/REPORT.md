## Threat and API limits

Original mutable metadata aliases may still be modified by their owner, but cannot mutate the privately copied snapshot. This intentionally differs from retaining the caller alias. A real execution change is still checked by the original independent genuine full boundaries; the snapshot is not a substitute for those checks. Normal callers can read nested mappings/sequences but cannot assign through them. The Target internal `_execution` field changes from dict/list to mappingproxy/tuple only on explicit opt-in. Existing derive_scope uses compatible reads, and canonical_bytes supports these types through original thaw. No other current module references Target._execution directly in the scoped search.

This proof assumes ordinary Python object access under the frozen trusted runtime. It does not resist a debugger, ctypes memory writes, gc-based recovery of private backing dicts, arbitrary source monkeypatching, or coordinated replacement of every internal field and its comparison pin. Existing Target authority likewise is not a security sandbox against such code. Source/runtime authority remains necessary and unchanged. No generic registry, raw mutable cache, injected authority or clock hook is introduced.

The selected copy has finite semantic byte/node/depth bounds, but those are not an exact whole-process physical allocation proof. Snapshot construction also temporarily thaws/serializes the copy; this and the retained Python object overhead must fit the future unchanged outer resource admission. There is no reservation increase in this candidate.
