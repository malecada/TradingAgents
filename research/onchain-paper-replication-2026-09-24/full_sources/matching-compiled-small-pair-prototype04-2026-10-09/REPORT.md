# Prototype04 loader ownership correction

Uninstalled source-only correction to independent review40c01924. Only _load_sealed, close and one terminal-error variable change. Exact AST inverse outside those scopes passes; matching_annealing.py, reduction.c and reduction.so are byte-identical to03. Original03 and both original failed workers remain untouched. Numerical/runtime eligibility and local-header constants are unchanged.

Loader success retains provisional memfd ownership until source close succeeds. Cleanup always attempts source close and, on failed/unsupported construction or failed source cleanup, owned memfd close independently. If cleanup fails, the original primary exception object is preserved where one exists; otherwise the first cleanup failure is raised. Bounded notes identify descriptor and uncertain cleanup. Unsupported OSError/AttributeError selects original fallback only after cleanup succeeds. An ambiguous cleanup never returns an enabled backend. Unexpected exceptions still propagate after both cleanup attempts.

Terminal close disables the function before its one close attempt. Successful close is idempotent. Failed close stores the original exception, leaves the route disabled and raises that same object on later close calls without retrying an integer descriptor that might already have been closed/reused. There is deliberately no claim of successful cleanup after close failure. This policy can leave a genuinely still-open descriptor until external process teardown; it does not invent closure or silently retry.

One stdlib-only CPU3/nice10 worker used AS512MiB/CPU30s/FSIZE4MiB/alarm30. Actual elapsed25,074,801ns; peakRSS18,776KiB. Actual extracted03/04 lifecycle functions ran against real opened fixture descriptors, with deterministic close failures before the underlying close and synthetic loader/seal stand-ins. This is lifecycle proof only, not new kernel sealing/dlopen/numerical or authority evidence.

Eleven focused cases include two original03 REDs (provisional memfd lost on source-close failure; original unexpected error masked), successful ownership transfer, source-only failure, both close failures with/without primary, owned-close failure retaining unsupported primary, clean unsupported fallback, clean unexpected-primary propagation, successful idempotent terminal close and failed terminal close preserving error without retry. Exact close-attempt order and actual remaining-open descriptors are recorded. Harness cleanup then explicitly closes residual fixture descriptors; candidate failure paths do not receive that cleanup credit.

Reuse03 accepted finite numerical, memfd and timing evidence only for unchanged bodies. No new numerical matrix or timings, no Main/Git/STATE/real data/Run/Owner/network/native changes. Universal compiled numerical equivalence, genuine runtime/library source admission and whole capacity remain separate and unproved by this correction.
