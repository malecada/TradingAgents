# Current-owner numerical sealing and registered outputs

This isolated successor wraps the accepted representation publication exactly once,
then hands live verification to an explicit terminal contract. It is not a cold
saved-artifact reader, historical continuation, native batch map or fit permit.

Both plan and selected execution job must bind the same seal policy and distinct
registered output names. Existing publication/seal attempts and outputs refuse;
no terminal identity is reopened. Before publication, the current pair state
must have no pending reservation and every latest pair result must be complete.
Actual current-owner lease replay is retained through the last live boundary.

The wrapper captures the actual published proof, exact proved feature-event
multiset, all admitted predecessor model-input hashes/extents, dictionary and
sampler proof/start/draw metadata, current claim/certificate/pair events and
registered inputs. New snapshots are bracketed by live ticket/owner validation.
Mixed directory inventories enforce known feature/pair event membership and
reserved pair sessions/artifact directories. Archived progress-state interiors
retain directory identities, exact member inventories and file signatures; their
numerical payload bytes are not newly hash-verified or restored. That limitation
must not be presented as full orphan/payload accounting or historical admission.

Feature terminal bytes are precomputed with lifecycle._encode, pair terminal
bytes with the pair journal encoder, and both output encodings with lifecycle.
The selected cap checks each before either seal, including completion/failure
metadata. Logical reservation is six metadata ceilings plus the 65536-byte pair
terminal ceiling: three own records, two outputs and the feature terminal. This
is not physical allocation/quota or total-memory enforcement. Snapshot entry cap
bounds metadata/tree membership bookkeeping; inherited resident inputs, source
checks, runtime and full streaming hash costs remain outside a performance claim.

A new phase-aware lease brackets both seals and individual output writes. It uses
the actual run/source/inputs/runtime/guard, pinned metadata and model-input bytes,
object identities, exact directories and precomputed terminal/output hashes.
Old owner/ticket/date leases are never relaxed or invoked after the first seal.
The two seals use the lifecycle lock. ResearchRun.write_json calls are outside
that lock because each reacquires it. Published output hashes must match both
saved bytes and the actual run registry. Unrelated preexisting published outputs
are retained. No implicit retry occurs after a partial output publication.

Failures retain last phase and all numerical/output evidence, including complete
and failed conflicts. The final immutable in-process receipt provides the terminal
lease and proof references. It does not authenticate a newly supplied cold proof
or publish a financial outcome. Producer replay is prohibited under the same
identity. Final independent acceptance requires closed integration evidence.
