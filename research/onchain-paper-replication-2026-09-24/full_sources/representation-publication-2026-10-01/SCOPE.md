# Durable current-owner representation publication

This candidate reserves one exclusive attempt before invoking the actual accepted
sequential closure. The selected output policy must agree between registered plan
and execution job; source, guard, current owner and upstream ticket checks persist.
The policy prepays four metadata ceilings plus one component ceiling as a logical
encoded reservation and bounds event count and snapshot entries. It does not
claim filesystem quota enforcement or total process memory coverage.

The unchanged full-prefix closure lease brackets a snapshot of every required
graph and MCM attempt directory and numeric component directory, plus the issued
dictionary and sample artifact component directories. The snapshot
pins exact directory identities/inventories and same-device, single-link, regular
file signatures and explicit admitted content hashes. Its entry cap is enforced
during enumeration. Proof/start/component hashes come from the actual closure;
array hashes and extents come from the exact hash-verified component manifests.
Snapshot receives explicit admitted SHA/byte pairs and rejects opened-file size
mismatch before any content read; it hashes only the admitted extent.
Snapshot capture and every check stream-verify file bytes with reads no larger
than262144bytes; newly observed bytes cannot silently become a trusted baseline. Retained prefix
metadata, owner/source checks, an actual registered denominator receipt and the
issued dictionary ticket cover the other prerequisites. This is a deliberate
handoff: the original closure lease is checked immediately before append and is
never relaxed or invoked with a changed prefix. After append, only one exact new
representation event is allowed. Prerequisite metadata, content hashes and file signatures remain
checked across the write; no prior arrays are loaded by snapshot checking.

The exact scalar-only schema3 binding component and its hash are constructed before
writing. The actual event and strict-inspected component must equal those exact
bytes/schema; array inventory must be empty. The completion proof includes the
full accepted closure, selected policy/source references, start, exact event and
component references, encoded counts and local predecessor signatures/hashes. Proof size
is checked before journal append. Partial, failed and completed attempts refuse
relaunch; failures after a partial write preserve their artifacts and failure
marker. Completion/failure conflicts remain visible rather than being cleared.

The FeatureJournal is deliberately left active/unsealed. This component does not
publish ResearchRun outputs, seal journal/owner, admit cold/historical/mapped reuse
or start a financial fit. Local signatures remain drift checks. Expected file hashes are also retained
and stream-verified; future saved admission must still join complete evidence,
content and ownership. Repeated full hashing can be expensive and is not a
full-fold performance claim.
The numeric closure, parent resident graphs, dictionary/sample arrays, Python
metadata serialization and page cache retain their earlier resource limitations.
No price exclusion, missing history or empirical registration requirement is
waived. The full paper architecture and scientific configuration are unchanged.

The new synthetic checks use actual two-graph closure fixtures and registered
sampler/dictionary/MCM/native graph artifacts, with kernel guard observations
mocked. Tests compare scalar component manifests against the actual serializer,
verify a completed event/proof and exact binding readback, refuse completed/failed
identity reuse, and inject stored completion-manifest corruption before strict inspection in the
initial version and during complete-proof writing in the corrected integration,
verifying failure/conflict preservation. No financial data or model fit is used.
