## Evidence retention and enforced bounds

Successful original control and diagnostic bodies are retained byte-for-byte in append-only hash-chained shards. Each framed record includes its original filename; no JSON re-encoding/truncation occurs inside the journal. Frame layout is little-endian name/raw lengths, UTF-8 original name, original raw bytes and32-byte chained SHA256. Every appended record is fsynced/read back. All shard membership, stat signatures, name uniqueness, stream lengths/count/head and EOF are fully audited. Context's actual terminal output anchors both journal heads/counts/encoded bytes/shard counts and poison flags. This is new declared storage encoding, not a claim that original standalone inode/path objects persist.

Successful empty command staging files remain until their exact descriptor is durably in a result record; only their zero-byte inode is then retired. Failed/nonempty output and original failed receipts remain standalone. A successfully exited lower command producing an oversized diagnostic is retained in full within failure headroom and causes an upper-layer failed operation; its original lower status is not rewritten. Oversized success-control records likewise retain exact original bytes in the finite failure area and refuse. Journal append/fsync failures preserve partial bytes and acknowledge nothing. No command is retried or refunded.

Selected caps separate cumulative rounded network payload IO from retained local storage. The diagnostic domain admits bounded receipt shards plus one original8MiB failed/inflight staging body and one128KiB original diagnostic. The source enforces that current diagnostic namespace contains at most two entries with the actual allocated current command name. There is no global4MiB numerical-file assumption. Controls reserve four bounded frames per command plus eight128KiB root/failure slots. Commands and reservations still spend before returning control; record/cardinality/byte overflow refuses. Success bytes exceeding a selected smaller cap never silently disappear.

The illustrative offline472000-command case with1024-byte controls/2048-byte diagnostics yields2,493,208,576 control bytes +1,114,887,680 diagnostic bytes and869 file slots, versus the prior309,339,357,184-byte/2,360,144-file calculation. This is enforced arithmetic for this source version, not a selected empirical policy or evidence the entire seven-graph workload fits16/20GiB. Original payload/replay counts, other archive/typed metadata, whole-union baseline, filesystem overhead and RAM still require exact Root accounting. Journal name indexes and shard pins also consume bounded-by-record-count Python memory; whole memory capacity is unmeasured.

Failure, clock reversal or expiration poisons the scheduler; expensive audit work is measured against the old timestamp before refresh.

This explicitly changes detection latency for closed evidence. There is no writer-exclusion grant, indefinite stat cache or guarantee that timestamps alone detect an adversarial rewrite. Full audits re-read raw bytes. A slow full audit may itself exceed freshness and stop the run; this candidate does not claim constant-time final audits or eight-hour feasibility.
