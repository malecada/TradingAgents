# Bounded compiled normalization prototype

Uninstalled engineering prototype, not a numerical source acceptance. Existing /usr/bin/cc (GCC11.4.0) compiled normalization.c with -O3 -fno-fast-math -ffp-contract=off, C11 and libm. No dependency install or network. NumPy2.3.0/SciPy are the pinned local runtime. Compiler invocation, version and source/output hashes are retained.

prototype.match keeps the actual matching_reference scalar RBF, initialization, alpha multiplication, ordered k/l edge updates with .5 coefficient, multiplicative beta schedule,48 iterations, stable row-major hardening and literal objective. Only scale → row-logsumexp → column-logsumexp → exp is replaced by the C function. The installed matching_annealing normalization sequence is the same sequence with chunk/state boundaries; the prototype does not implement checkpoint/state/authority boundaries and is not a substitute PairExecutor. Domain is contiguous float64,1..32 rows/columns, finite nonnegativeQ, positive finitebeta with finite products, nearest rounding. Output allocation is at most8192B; C reduction uses scalar temporaries, no dense extra scratch.

C reduction follows the installed SciPy maximum-exclusion formula: count maximal entries, sum exp(nonmax-max), divide by maximum multiplicity when nonzero, then (log1p(sum)+log(multiplicity))+maximum. Row then column order is retained. C sums are sequential; NumPy can use pairwise reductions depending on axis/size. Scalar libm exp/log/log1p need not be bitwise equal to NumPy vector ufuncs. No fastmath/FMA contraction/lower precision. These are explicit remaining arithmetic differences, not silently accepted. NumPy warning/error callbacks and floating-point exception partial-state semantics are not reproduced. There is no production fallback or source/currentness guard in this prototype.
