Two-worker feasibility and design decision

The current6GiB cgroup,5GiB memory.high, zero swap, two CPU IDs/200% CPU quota and TasksMax64 apply to the entire job (resources.py:550–557; job.py:44–64). Two workers plus the parent share these limits;16GB physical RAM does not enlarge them. The parent must retain the weekly population and neighborhood index once. Fork risks inheriting that population, open transport descriptors, locks, authority objects and initialized numerical runtime. Prefer two persistent spawn/exec workers with sanitized environment and explicit inherited CPU/cgroup checks. Never send weekly graphs, credentials, ResearchRun, original Owner or closure-bearing callbacks.

Only local immutable neighborhood/motif arrays and plain matching configuration may cross IPC. 'Local' does not mean small: current extraction_limit350,110, effective pair entries8,402,640, max_state_bytes275,241,856B, hardening_buffer143,195,398B, and per-checkpoint269,097,984B are substantial. Two state limits alone total550,483,712B; that excludes worker runtimes, parent index, temporary numerical buffers, transport copies and checkpoint reconstruction. Some state/scratch allocations overlap or alias, so adding all declared limits is not a proved peak. Sending an8MiB numeric-cache key is not an8MiB graph limit: uncachable larger pairs still exist. Preflight must reserve worst-case bounded IPC/worker memory or explicitly choose original serial execution for oversized pairs without changing scientific coverage.

The smallest useful route is at most two distinct in-flight pair tasks within an original journal batch, with parent memo/cache decisions and ordered commitment. Driver task generation is serial at batched_driver.py:16–38,130–139; memo cache lookup/store/receipt order is batched_numeric_reuse.py:259–288. A simple executor swap remains serial. Blind two-item prefetch computes future cache hits unnecessarily and may alter their origin/LRU order; deduplicate in-flight keys, retain original committed cache updates, and mark abandoned speculative work without giving it occurrence credit.

Children may compute later pairs ahead, but no later result, error, checkpoint or budget increment becomes public before all prior occurrences. A later checkpoint must block with one bounded snapshot; parent invokes the unchanged checkpoint publication on the original pair ordinal and updates global counters once. The first error is the earliest ordered occurrence, with later work cancelled and a bounded failure-only list of speculative statuses retained. Every IPC message needs explicit framing, byte bounds, schema, purpose/ordinal/config/source hashes and deadline; avoid arbitrary unpickling. Reconstruct exact dtype/shape/readonly buffers and validate checkpoint state before parent publication. Pipe/socket buffers, serialization and duplicate checkpoint arrays must appear in the memory budget.

Cross-process authority is the difficult semantic change. No worker may invoke a fake Owner or claim independent authority. Parent services genuine validation requests at each original PairExecutor polling seam (89,95,103–106). Strict globally ordered validation makes the second worker wait and can erase parallel benefit. Interleaving genuine polls permits parallelism but changes their timing and permits bounded speculative progress under revocation. That must be explicit opt-in execution semantics, with no suppressed original checks or stale-success cache. Parent waiting must continue servicing polls; a single blocking large IPC read or checkpoint save can otherwise starve the60s lease. Do not implement before selecting and reviewing this policy.

On failure/close, terminate then kill if needed, wait/reap both exact PIDs and verify same-cgroup disappearance; do not replace workers until prior death is established. Preserve primary errors plus cleanup uncertainty. Existing KillMode=control-group and terminal cgroup checks cover descendants at the outer layer (resources.py:704–718), while verify_cpu_tree checks every descendant thread (132–147). Parent-death binding exists at856–860 but is not automatically installed in proposed workers. Abrupt parent death, blocked IPC, dead child, stuck checkpoint, cancellation, callback failure and kill/reap failure all require deliberate qualification. No multiprocessing code was completed; source-only node-caller work is separate and must not silently enter this plan.
