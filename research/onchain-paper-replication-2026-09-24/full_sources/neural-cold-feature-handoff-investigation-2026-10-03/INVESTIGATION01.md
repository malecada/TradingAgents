## 1. Exact resident ownership and release boundary

`job_payload.py:224–240` eagerly loads the entire descriptor's `graph_population`, not just the next batch or even only `required_graphs`. The compact route selects `load_graph(..., resident=True)` at line 192. `graph_store.py:69–83` reads every declared graph member, converts node IDs into Python strings, constructs and validates a `GraphSnapshot`. `contracts.py:12–35` makes its arrays immutable via copies/backing bytes. It is not an object with a release method. Its storage becomes reclaimable only when every reference and backing alias is gone; disk-file extent does not measure that resident storage or Python overhead.

The following live chain remains reachable after the producer returns:

- `compact_native_features._Features._terminal` (`compact_native_features.py:43–46`) holds the terminal receipt. The `_NativeMap` lease/read callbacks also close over that same receipt (`:96–98,129`). Removing only the wrapper's field would not sever the chain.
- `compact_terminal.Receipt._verify` and `_live` close over `published`, `closure`, owner, stage objects and other state (`compact_terminal.py:138–198`). `verify()` calls `published._evidence()` even in metadata mode; its source closure also refers to the original graph/dictionary/training receipts. `full=True` calls `_original()`.
- `Published._closure` → `Closure._graphs` → every published graph's `_features._mcm` holds the original MCM matrix and original graph (`compact_publication.py:30–35`, `compact_closure.py:66–70`, `compact_graph_artifacts.py:109–111`, `compact_mcm.py:122–125`). Thus the retained population includes all completed MCM matrices, not only original GraphSnapshots.
- The dictionary proof → published samples → draws → `Training` holds all original graphs, training graphs, samples and dictionary ancestry (`compact_mcm.py:34`, `compact_sample_proof.py:116–139`, `compact_samples.py:146–154`, `compact_sampler.py:109`, `compact_training.py:174–181`). `Training` deliberately stores original identity aliases and checks them at `:205–208`.

`compact_terminal.py:130` explicitly records `resident_originals_retained=True`. Its full check rehashes original graphs and MCM/feature lineage (`:30–54`). `compact_native_producer.finalize()` requires exactly the current `_Features` type and full terminal checks (`:188–198`); `job_payload.py:214–220` invokes it both before and after the batch. These checks cannot safely be made no-ops to free memory.

Deleting the local `graphs` variable in `_produce_eager_graphs` is insufficient. Clearing `Training._graphs`, replacing `_mcm._graph`, nulling the original receipt's callbacks, or manufacturing a plain `FixedFeatureMap` bypasses identity, content or authority checks. Merely checking `owner.closed` is also insufficient: stage completion, representation publication, whole-run completion and empirical admission are different states.

## 3. Minimal prospective implementation seam

Prefer an optional same-run post-publication handoff over forcing an extra historical producer claim merely to reclaim memory. The current producer already performs full numeric/readback checks before finishing its Owner. A new route can authenticate that completed boundary once, then verify immutable saved evidence independently, allowing the old object graph to become unreachable when its stack unwinds. This requires new source; it is not a currently callable capability.

1. **New strict detached authority module.** Add a distinct typed factory/receipt, for example `compact_cold_features`, selected by an admitted execution-policy input in both producer plan and job. Its factory accepts only the exact genuine current terminal, calls the existing full terminal verification under the original transition discipline, and requires the current run, closed unpoisoned owner, all required completed stages, successful compact publication, exact registered output hashes and absence of conflicting failure markers. It must not accept arbitrary callbacks, serialized owner booleans, an imported Dictionary in place of `Produced`, or a user-supplied content hash as authority. Do not change old terminal bytes or their `resident_originals_retained` statement; a new handoff receipt identifies the later state.
2. **Detached evidence contract and lease.** Freeze a bounded, explicit set of descriptor/science and owner identities, admitted input/source/runtime pins, parent/stage/terminal/publication/graph artifact metadata hashes, original path/inode signatures and output registry joins. Reconstruct the compact marker and publication schema exactly. Include dictionary/source/ordered motif/node-order/edge lineage, full required graph set, train/fold/seed/configuration and denominator. Recheck saved component bytes sequentially and exact directory membership using held-file/readback protections. Preserve archive/stage seals and operation-population joins where selected. The new authority checks current source/guard/run and saved evidence before/after reads and fitting; it must not close over `Receipt`, `Published`, `Closure`, `Training`, original GraphSnapshots, MCM matrices or producer-bound methods. A generic JSON snapshot alone is not an authenticated capability. Metadata leases remain distinct from full numeric content checks.
3. **Explicit producer/adapter dispatch.** Extend the selected route in `compact_native_producer.selected/produce/finalize` and source closure. Preserve the resident default. On the new path, return a `PreparedFeatures` whose mapping retains only the detached authority and file references. `compact_native_features` can remain unchanged if the new module supplies its own wrapper over the existing `_NativeMap`; do not loosen its exact old Receipt check. Refactor only a common read-only reference-validation helper if needed and verify both routes. `finalize` must branch on genuine route/type and perform equivalent saved-content/output verification, not skip the second check.
4. **Caller lifetime.** In `job_payload._produce_eager_graphs`, ensure no second returned resident terminal is kept by `_`, closures, exception state or the prepared result after return. Return only the detached product on the selected path (or a detached second value if compatibility requires the tuple). Do not explicitly destroy a still-live mapped population or alter old immutable objects. Prove normal frame unwinding releases every strong producer reference. Keep `execute_fit_payload`'s pre/post-fit finalization; separately retain any externally held alias in the accounting.
5. **Protocol/source binding.** Add the execution-policy input, source closure, output/watch membership and a declared transition to the exact prospective gate. Keep the actual schema-3 scientific binding unchanged when its mathematics/provenance are unchanged; pin the new execution policy separately so config/admission evidence does not silently conceal a new backend. An exact implementation may need a versioned job/plan field validator. Do not rewrite historical descriptors, sources, results or journals. No need to alter model/GAT/training math or relax `resources.py` for this lifetime change.

The file-backed verifier is the material new correctness work. It must preserve the guarantee actually needed after the transition—same admitted durable inputs/components and full scientific provenance—while explicitly retiring, rather than pretending to continue, an original in-memory identity check. The original receipt remains valid under its old contract if another caller retains it; such external retention prevents the memory-saving claim. No in-place revocation/deletion of historical evidence is proposed. A separate terminal-to-cold state machine must refuse concurrency and duplicate handoff, preserve the first fatal error/closure failure, and fail the enclosing new job after post-fit evidence failures even if individual cells already completed.

A two-process/historical-reuse design is a larger alternative: add a genuine representation-only dispatcher/terminal and a compact-specific completed-history reader, prove producer death, then independently admit a consumer. Existing `job.py:277–322` does not provide that stage: the `fit` worker runs `execute_fit_payload` and only finishes its lifecycle afterwards. The resource-only import dispatcher is not that stage either. Do not mark the active run complete halfway through fitting or reopen a closed identity. This alternative has additional lifecycle/source-transition/registration requirements and is not the minimal same-run seam.

## 4. Batch, gradients and memory guarantees that must survive

The detached route changes fixed-input ownership only. `evaluation.batch_factory:31–38` must still materialize one feature object per graph hash per batch, then repeat that same object at every required sequence position. `model.forward:82–95` caches by `id(graph)` within one forward; exact object reuse matters as well as the hash. Preserve original sequence order, batch size 16, 28-day lookback, eligibility/gaps and masks. Do not cache learned embeddings between optimizer steps, detach them, pool/reduce graphs, change graph memberships or replace joint GAT/LSTM gradients with fixed embeddings. Repeated appearances must contribute their gradients through the one shared forward graph; dropout/RNG and checkpoint recomputation remain unchanged under the separately selected execution policy.

The `_NativeMap` implementation (`terminal-output-lifetime-2026-10-01/native_map.py:103–126`) already deduplicates selected keys and tracks still-live original returned tensor wrappers. Its allowances are not full storage-lifetime or process-RSS bounds: aliases/autograd, external dictionaries, parent graphs, model state and Python overhead remain outside them. A new handoff cannot claim these allowances cover all memory. `verified_hashes` also reads each saved graph sequentially before training; include that phase and its temporary peak. Same-run deallocation makes memory reclaimable but does not prove the allocator returns RSS immediately.

Keep the existing outer guard, current full-neural resource caps and 3 GiB reserve. `resources.py:203–221` requires startup to cover cap plus reserve; a detached authority does not make low current MemAvailable eligible. No cap ladder or new full-size probe is authorized by this report. The original 04 kernel OOM used one retained real graph and synthetic MCM, not this full compact producer chain, so this handoff does not by itself explain or cure that failure.

Preserve original fatal identity and all partial evidence. Pure mocks qualify interface checks only.

The subsequent genuine native tiny proof should construct a complete scientific compact representation with synthetic examples and the actual owner/denominator/publication/terminal route, then call the new factory. It must not substitute the original-import two-target resource terminal. Freeze the caller, admitted kind/factory, full source/runtime/input/output closure and finite native limits first. If that actual scientific route is not yet available under the engineering caller, document and implement the missing seam; do not counterfeit a Binding or mark a resource journal scientifically complete.

Use weak references/identity accounting to demonstrate that all original producer graphs, MCM matrices, samples and closures lose internal strong references after the caller unwinds, while the detached map still validates and loads correctly. Include a deliberately retained external alias as a negative control: it must remain accounted for and must prevent a blanket release claim. Repeat hashes within a synthetic 16×28 batch, include gapped eligible rows and a short final batch, compare original versus detached values/object reuse and a fixed forward/backward/optimizer step. Test alias mutation, second-batch prior holds and post-forward/post-backward ownership. Native before/after/current and peak observations are separate from weak-reference evidence. No result from these future checks is claimed here; the earlier 3,823 bitwise-equal checkpoint comparisons did not exercise this handoff.

For the real question, the previous census's missing immutable daily-example projection, feature manifests and complete graph/window/scaler/denominator context are still required. An eligible real full-batch union cannot be inferred from nine isolated pilot weeks, assumed seven weeks or 28 distinct hashes. Parent-only holds and per-batch distinct MCM/edge bytes need separate measured denominators. Completed real feature production and detached loading may fail before model fitting; preserve each unavailable/failed disposition.
