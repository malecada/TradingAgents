# Independent production-integration audit

The accepted isolated ranked composite is not a drop-in replacement for the registered matching route. The minimum safe integration needs an explicit numerical backend identity, an owned pair-checkpoint protocol, and journal/caller support for partial directional scores and partial MCM rows. No production change or empirical release is approved by this audit.

This is static inspection at HEAD `e6417c6f2f59c1ccf9fdb9ffd2af4c5b59020977`. All 100 bindings of the concurrently active directed-chain profile still match. No source, gate, ledger or existing evidence was edited; no test/profile, numerical replay or empirical body read was performed. File references below are relative to `tradingagents/research/onchain_replication/` unless another prefix is given.

## Integration-blocking semantic gaps

**1. The current retention policy cannot carry a solver substitution.** `matching_policy.py:1–14` admits only schema 1 / mode `score_only`, deliberately leaving solver identity unchanged. `registered_features.py:126` turns any admitted matching policy into a boolean, and `feature_pipeline.py:141–143` forwards that boolean to MCM. `mcm.py:15,30–31` interprets it as the existing accelerated route, explicitly forbidding `reference=True` with score-only. Simply branching on this flag would silently redefine an already admitted policy.

Production dictionary distance uses scalar `match_reference` twice (`dictionary.py:71`), whereas default MCM uses Torch (`mcm.py:30–31`). Torch computes vectorized affinity/reductions, batches equal shapes and emits a float32-rounded score (`matching.py:50–82`). The isolated composite uses scalar/SciPy arithmetic and returns the sparse scalar float64 score (`full_sources/matching-ranked-composite-2026-09-30/combined.py:95–103`). Casting the latter to float32 at MCM storage does not establish the same assignments or reductions as Torch. The retained precision amendment explicitly requires float64 solve and float32 reported accelerated similarity, and does not grant GPU parity (`matching-precision-v2.md:9–15` under the study root).

Required change: a distinct, versioned numerical implementation descriptor, separate from result-retention and resource allowances. It must declare scalar versus Torch engine, CPU/device, affinity/normalization/accumulation and output precision, hardening tie order, objective/domain version and batching behavior where applicable. Preserve absent-policy and current schema-1 behavior. A scalar reference-compatible dictionary path is the smaller initial target; switching MCM requires a separate deliberate numerical compatibility decision. Do not claim exact Torch parity from the synthetic scalar-reference fixtures or the active profile.

**2. Existing cache and workflow identities do not distinguish that substitution.** Dictionary checkpoint identity hashes samples, matching configuration and dictionary configuration (`dictionary.py:57–61`); the final dictionary hashes `matching_config_hash` and contents (`dictionary.py:94–100`). Representation identity uses graph population, fold, train hash, arm, seed and configs (`feature_pipeline.py:68–73`; `registered_features.py:24–30`). Existing matching execution policy is recorded in the producer claim (`registered_features.py:113–118`) but omitted from those numerical identities. That is appropriate for the existing same-kernel diagnostic-retention change, not automatically for a different solver.

`cache.py:93–113` has an `ArtifactKey` requiring source commit, configuration, fold, membership, dictionary and weights, but the above workflow/dictionary paths use `cache_key` directly. The generic key does not automatically protect them. In particular, the same required graph/config identity could otherwise admit an old float32 MCM prefix and append newly computed scalar-backend values under one unchanged workflow.

Required change: bind numerical backend/version in the execution/cache namespace and enforce it on partial and completed reuse. A proven reference-equivalent implementation may preserve a scientific dictionary content identity, but cross-backend reuse still needs an explicit compatibility rule rather than source-commit omission or tolerance alone. Keep resource ceilings/chunk policies distinct from science; the actual pair checkpoint must require the exact policies under which its state was saved. Preserve old identities and readers; introduce a versioned reader/descriptor or an explicit old-to-new compatibility path, never reinterpret historical bytes.

**3. Dictionary continuation loses partial directional work.** `fit_dictionary` calls both `A→B` and `B→A` synchronously before writing one symmetric distance, then checks elapsed checkpoint time (`dictionary.py:67–74`). A long first solve, second solve or atomic normalization/sort can exceed the nominal 600-second interval before any callback. A failure between directions cannot reuse the first completed score. Current `resume_state` contains only completed distance matrices; it has no active ordered pair or directional completion record. `_distance` at `dictionary.py:28–34` is a second legacy full-solve route that must not become an accidental bypass.

Required change: a deterministic pair-work key containing sample identity, exact ordered left/right graph hashes, partition/index sequence, direction, numerical backend and config, plus current owner/source and admitted parent lineage. Retain `A→B` completion before starting `B→A`; publish the symmetric distance only after both exact scores exist. Keep sample ordering, PCG64 partition reconstruction, average linkage, tie handling and expanded membership untouched (`dictionary.py:76–95`). Do not assume symmetry to omit the reverse solve. Reject conflicting completed distances or omitted prior progress rather than silently recomputing them.

**4. MCM continuation is only at completed rows.** `mcm.py:27–34` builds all motif pairs for one neighborhood, computes the entire list, writes one row and only then checkpoints. Pipeline recovery stores a float32 prefix and `next_node` (`feature_pipeline.py:135–144`). An expensive motif pair cannot be resumed, and a partially computed row has no durable denominator. The current final prefix check does not encode motif-level progress.

Required change: bind graph hash, node-order hash, center index/ID, exact neighborhood identity, dictionary identity and representative order, motif index and ordered pair identity. Persist completed motif scores and the current pair checkpoint separately; advance `next_node` only when every motif in the row is durable. Keep an explicit completion mask/cursor rather than treating zero as missing. A resumed complete score must be reused, while a genuinely unfinished pair continues from the pinned safe boundary. Persist the declared output dtype, and reject mixed numerical backends in one row/prefix. Release local neighborhoods and mapped rank state before the next pair/center, preserving the existing `del scores,pairs,local` lifetime intent.

**5. No registered journal owns the isolated pair directories yet.** The composite's `save/load` bind graph/config state and trusted manifest hashes, but not a ResearchRun lease or producer/cell identity (`combined.py:106–144`). FeatureJournal currently recognizes only seven coarse stages (`feature_journal.py:9–10`), writes generic component payloads and event hashes (`:50–61`), and reconstructs dictionary matrices or MCM prefixes (`:94–119`). Generic `checkpoints.py:20–54` is neural model/optimizer/RNG state, not a matching-pair resume mechanism. Loading any of these does not admit a run.

Required change: a versioned journal event/reference for a matching sub-artifact, including exact manifest hash, schema, owner, ordered pair, source/runtime/backend, phase, safe cursor and policy. The state-machine arrays should stay in dedicated streamed files; do not serialize every dense state into a generic JSON payload or route it through `cache.publish`/`read_artifact`, whose member interfaces materialize bytes (`cache.py:20–40,64–89`). Derive exclusive directories under the admitted current producer filesystem, validate containment before mkdir, and publish the reference only after durable state publication. Handle a publication gap with explicit retained artifact reconciliation; do not pick the newest directory by convention.

A successor must retain the existing failed-parent checks and full ancestry closure (`registered_features.py:92–110`; `feature_journal.py:73–99`). A complete producer is reused, not reopened. An old pair checkpoint may be read from a failed parent, but all new checkpoints belong to the new admitted owner and must never overwrite parent bytes. Source-version compatibility must be explicit; an outer source commit pin does not prove arbitrary checkpoint schema compatibility.

**6. Checkpointing does not remove remaining capacity and time constraints.** The new composite retains `32*n*m` numeric bytes, admits separate ranking and score buffers, and saves up to `32*n*m+512+3*65,536` logical bytes per checkpoint (`combined.py:24–40,95–118`). It still hashes/validates full inputs, performs atomic rank creation, and scores atomically (`:66–103`). The old 4,000,000-pair guard remains (`matching_reference.py:23–31`), while the frozen dictionary still caps neighborhoods at 10,000 nodes. Neither should be raised, truncated or bypassed as an incidental integration choice.

Required change: aggregate pair state, prior output prefix/distance matrices, sampled graphs, neighborhood indices, full graph population and multiple retained checkpoints under an explicit job resource policy. Bind total checkpoint count/bytes/free-space limits, account for physical allocation where promised, and retain failed partials. The current elapsed callback after a pair/row is not proof of a maximum atomic time. Either qualify a finite per-pair guarded attempt with preserved failure or implement separately reviewed interruption of the remaining atomic stages. Full-fold feature arrays and copies (`feature_pipeline.py:135–144`) remain a separate feasibility issue even if one pair fits.

## Minimal testable integration sequence

1. **Freeze numerical and ownership contracts before changing consumers.** Define the distinct scalar-ranked backend and output conversion, exact pair artifact schema, policy and old-state rejection rules. Promote reviewed code into maintained package modules with normal imports; do not import dated study directories from production. `job.py:27–32` automatically requires package `.py` files, but dated prototype modules are outside that closure. Extend runtime/config/source pins and named offline coverage; pin NumPy/SciPy behavior and CPU semantics. Preserve original prototype and profile evidence.
2. **Implement a single-pair registered adapter first.** Own `create/advance/save/load/close`, derive exclusive paths, pre-admit budgets, and bind exact ordered input identities. Test uninterrupted versus resumed soft bytes, ordered assignment/score/convergence, changed orientation/backend/config/source/policy rejection before allocation, corruption, poisoning, pre/post-publication interruption and real mapping closure. Inject failure after score completion to prove completed-score reuse without solver re-entry. Do not use hostile prefix replay as a claimed guarantee of the existing structural checker.
3. **Integrate dictionary continuation on the scalar path.** Test interruptions before and after each direction, between pair publication and symmetric-distance publication, and across recursive partitions. Require exact distance matrices, medoids, hierarchy and full dictionary identity versus uninterrupted scalar reference. Instrument solver calls to prove that completed directions are not repeated. Preserve train-only sample membership and fold/time bounds; matching must not select examples or inspect labels.
4. **Integrate MCM under an explicit numerical policy.** Add partial-row and pair references while preserving current default Torch paths. Test changed motif order/center/local graph, incomplete rows, dtype mismatch and wrong backend rejection; then real registered failed-parent continuation with exact completed-pair reuse and unchanged parent evidence. Require final feature/binding equality within the same backend, and separately apply the established accelerated/reference tolerance and tie-feasibility policy. Do not promote tolerance to exact cache interchangeability.
5. **Wire admission before numerical work and verify end to end.** Extend the existing all-job preflight (`job_payload.py:51–78`) and producer recheck (`registered_features.py:33–64`) with exact input-name/hash/backend/policy agreement, unused-policy rejection and source closure. Version final bindings/readers as needed (`feature_pipeline.py:170–176`; `feature_journal.py:125–132`). Add an actual small lifecycle test through plan admission, graph loading, dictionary, MCM, failed journal, successor and completed reuse. Verify no pair checkpoint is accepted merely because its path exists. Then run focused and named offline verification on frozen source before any new empirical release.

This sequence may proceed as ordinary synthetic engineering only after the active profile releases its frozen source ownership. New empirical work still needs its own exact committed gate, capacity checks, budget/denominator preservation and independent release. The active full-chain profile's outcome was not used or inferred for this audit.
