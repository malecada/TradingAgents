# Independent mapped-graph loader design review

September 29, 2026. Reviewed the proposed API against current graph storage, GraphSnapshot contracts, canonical hashing, neighborhood sampling, feature production and alignment source. Source-only design review: no arrays, raw artifacts, tests, jobs or external requests were opened or executed. No empirical registration or allocation is enabled.

**Disposition: suitable for bounded synthetic implementation, subject to the contracts below.** Keeping the existing eager loader and immutable GraphSnapshot construction unchanged avoids silently weakening current callers. The new API should promise context-owned read-only mapped storage and a declared mapped-file ceiling, not globally bounded graph computation or snapshot isolation from external file mutation.

## Identity and validation

The subclass must have exactly the inherited dataclass fields, with no owner, mode, path or closed-state fields. Current `graph_hash` hashes `fields(graph)`; adding even an execution-only dataclass field changes scientific identity. Override initialization carefully so only admitted mapped arrays and IDs avoid copies. Preserve immutable source hashes and exclusion metadata. Do not weaken ordinary GraphSnapshot's defensive copying or permit mutable caller arrays to enter the mapped subtype as if they were validated file maps.

**Mapped ID validation must apply at every validation entry point.** Current `validate_graph` sorts `g.node_ids` into Python objects, and graph hashing, sampling and feature production repeatedly call it. A bounded loader-only check followed by this existing validation recreates the allocation being avoided. Select bounded nonempty-string and strict adjacent-order checks for the mapped subtype wherever it is validated; overlap block boundaries. Reject unsorted mapped IDs without reordering. Preserve the eager contract, which currently accepts unique unsorted IDs. Unicode storage must be one-dimensional with fixed-width Unicode dtype; object, byte-string, structured and malformed dimensional variants need explicit rejection.

Other current graph validation allocations remain material: endpoint duplicate detection builds a linear lexsort index; finite checks, aggregate comparisons and `log1p`/`allclose` can allocate full-array temporaries. Bound appropriate scans or state these costs explicitly. Memory mapping alone does not make the entire validator constant-memory. Preserve endpoint dtype/range, duplicate edges, dimension, finite attribute, aggregate/log agreement, clock, source hash and count conservation rejection semantics. Do not silently broaden accepted numeric types or change tolerances.

The streamed node-order identity must reproduce `cache_key(tuple(ids))` byte for byte, including JSON punctuation, Unicode encoding and escaping, not hash array bytes or concatenate unseparated IDs. Check zero/one-element cases, escaped and non-ASCII strings, and both sides of chunk boundaries against the legacy oracle. Use this helper in feature lineage without expanding IDs to a tuple. Canonical graph hashes must remain equal across eager and mapped representations, C/Fortran layout and supported byte orders; logical iteration order is the identity, not storage order.

## Admission to mapped files

Before any mapping, validate the complete member denominator: required `node_ids`, `node_features`, `edge_index`, `edge_features`, plus only the existing optional `edge_aggregates`. Reject missing/unknown names, aliases and paths other than the exact expected filenames. Validate positive actual-integer limits and integer declared sizes (reject booleans), sum all declared member file bytes including NPY headers, and compare the sum to the explicit ceiling. Stat every member and reconcile physical versus declared size before expensive hashing or mapping; a dishonest tiny declaration must not bypass a huge file. Check manifest and each member hash, supported safe NPY headers/dtypes, actual shape/data extent and `allow_pickle=False`. A manifest/header size bound is needed for any claim of bounded metadata allocation; otherwise qualify that exclusion.

Reject symlink members and document the ancestor/file stability boundary. Read-only mappings prevent writes through this API but do not make the backing files immutable against another process; truncation or mutation can invalidate hashes and even fault later reads. The intended environment must preserve published graph files and hold them stable for the context lifetime. Avoid describing a pre-open hash plus ordinary path reopening as protection against hostile replacement races. This design does not grant permission to move or rewrite retained bodies.

## Ownership and failure behavior

Track every opened mapping immediately, before later member opens, GraphSnapshot construction, validation or content hashing. A failure on the last member must close all earlier maps. On normal exit or a body exception, attempt every close even if one close fails; preserve the primary failure and surface cleanup failure without false success. Read-only mapping closure requires no data flush. No scratch files, automatic repair, retry or resume should be introduced.

The mapped graph and any raw-array views are borrowed for the context lifetime. Closing `_mmap` while an escaped ndarray view remains can create unsafe dangling access; merely documenting a read-only flag does not solve ownership. Require callers to keep the context alive while any raw view is used, and ensure returned samples, dictionaries, features and bindings own their data before the context closes. The current AttributedGraph constructor copies arrays, and feature production constructs new Torch tensors, but this must be demonstrated for the paths claimed. Tests should inspect ownership before closure and use independent outputs afterward; do not intentionally dereference a closed raw mmap in-process. Alignment retains prior node IDs internally, so all graph contexts needed by that operation must remain open until it finishes.

## Meaningful verification and scope

Compare eager and mapped graphs, canonical graph and node-order hashes, full sample records/RNG/identity, dictionary identity, MCM values and complete feature bindings on actual synthetic pipeline fixtures. Then close every graph context and verify retained output values remain usable and independent. Assert mapped backing and read-only buffers without relying solely on class names, and prove ordinary GraphSnapshot remains isolated from mutation of constructor inputs.

Negative tests should include oversized declared totals before the first mapping, dishonest sizes, corrupt hashes, missing/extra/unsafe members, invalid numeric/ID dtype or shape, unsorted IDs, duplicate IDs at a validation-block boundary, duplicate edges, invalid counts/clocks and aggregate mismatch. Exercise no-aggregate and empty-array cases according to the existing contracts. Inject a late open/validation/hash failure and one close failure; assert that all other mappings are closed and exceptions are preserved. Test direct revalidation and graph hashing do not restore full ID-list allocation.

This component alone does not admit full-fold loading or reduce adjacency indices, alignment sets, retained neighborhoods, matching matrices, Torch copies or model activations. `max_mapped_bytes` is not a peak-RSS, page-cache, total virtual-memory or disk-capacity claim. The outer guard and prospective registered graph-residency policy remain necessary before empirical use. No resource pilot, sample replay, financial fit or completion criterion follows from synthetic loader acceptance.
