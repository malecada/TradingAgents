# Opaque POSIX reconstruction helper — source-only candidate

`recover.py` reconstructs an externally supplied, fully bound preservation bundle into an exclusively created new root. It never opens any row's original source_path or resolved_path. It does not transfer/download, delete, retire, overwrite or grant owner/scientific authority. Actual original data and active native22 remain untouched. New source, toy fixtures and receipts are confined here.

## Exact API

All three calls require complete normalized CONTENT_ROWS and DIRECTORIES from one externally admitted snapshot, original_root, max_files, max_total_bytes and max_file_bytes. File rows require relative_path, source_path, resolved_path, kind='regular', full stat mode, integer mtime_ns, bytes==logical_bytes, nlink1 and expected_sha256; optional posix_mode must agree. Directory rows require relative_path (including exactly'.' for root), source_path, kind='directory', full mode and integer mtime_ns. Additional original identity/allocation fields remain bound in bundle member rows, but cannot be reproduced as new inode/device/ctime/allocation identities.

1. `create_new_tree(target_root, rows, directories, *, original_root, max_files, max_total_bytes, max_file_bytes)` creates root and every explicit directory exclusively, with temporary0700 permissions. It returns the new root(device,inode) pin. Every ancestor is opened component-by-component with O_DIRECTORY|O_NOFOLLOW; an existing root or redirected component refuses. Target/original namespace overlap is rejected.
2. `recover_bundle(archive, manifest, expected_rows, target_root, *, directories, original_root, root_pin, batch, max_files, max_total_bytes, max_file_bytes, max_archive_bytes)` accepts one exact batch record `{index,start,stop,raw_bytes}`. It requires every ordered manifest member to equal the supplied expected_rows slice plus generated `member='files/NNNNNNNN'`. The actual preservation API uses **member**, not tar_member. Canonical JSON comparison distinguishes integer/float/bool metadata mutations that Python dictionary equality could conflate. Archive/member/payload bounds are checked before verification/extraction. The existing unchanged preservation.verify_bundle verifies the complete archive and member hashes before output writes; extraction again verifies each member's bytes while streaming at most1MiB. Original source references are metadata only.
3. `verify_new_tree(target_root, expected_rows, directories, *, original_root, root_pin, max_files, max_total_bytes, max_file_bytes, restore_directories=False)` verifies exact whole file/directory inventory, no extra paths, regular singly linked files, byte extents, hashes, complete mode and mtime. After **all** bundles, call once with restore_directories=True: it first verifies every file and namespace, then restores directory permissions/times deepest-first and root last, with fsync/readback. A later false call checks the finalized tree without changing directory metadata. Missing files refuse before directory restoration. No per-batch directory finalization occurs.

Full `st_mode` values retain their type bits in expected metadata; fchmod receives only `stat.S_IMODE(mode)`. Readback compares full new st_mode. Nanosecond mtime is restored/read back; atime, ctime, inode, device, sparse layout and allocated block identity are not claimed. Directory logical byte sizes are filesystem-specific and deliberately are not treated as reconstructable content extents.

Archive paths must be canonical regular single-link files outside original_root. Archive identity is checked before and after the existing verifier, before extraction and after extraction. Target files use openat with O_EXCL|O_NOFOLLOW; parent directories are descriptor-walked with NOFOLLOW. Files are never overwritten. Each recovered file is hashed and metadata checked before its directory is fsynced. Root identity is rejoined through the actual pathname before successful return. Errors preserve created partials; no cleanup, unlink, resumable overwrite or rollback is implemented. Root must retain failed outputs and choose a fresh recovery namespace rather than repeat an occupied batch.

## Focused verification

TEST01 passes a three-file toy inventory (opaque binary, text bytes and empty file), original nondefault0640 file/0750 directory modes and exact ns timestamps. Real preservation.build_bundle/verify_bundle produce/check both a complete bundle and two successive bundles retaining original numeric start indexes. Whole reconstruction passes; a second verification confirms finalized metadata. The wrapper records calls to the actual existing verify_bundle, without replacing its implementation.

Refusals cover parent/absolute/dot/empty/backslash paths, original-root overlap, existing root, symlink root/file, overwrite, hardlink file, extra directory, wrong root pin, typed manifest metadata, member order/count, too-small file allowance and truncated member bytes. Refusal fixtures and partials remain. No NumPy/SciPy/Torch imports occurred.

Runtime readback records affinity **[0,1]**, i.e. two logical CPUs overlapping the active native affinity (neither isolated CPUs nor the single CPU numbered2), nice10, AS268435456B and FSIZE4194304B. The command used a60s timeout. Source fixture/test logs are bounded; no real graph or original xsect content was read. No failed attempt was discarded.

## Required outer contract and limitations

This helper does not establish remote completeness, latest-snapshot eligibility, source inactivity, writer exclusion, available RAM/disk, permissions to mutate an original namespace, or retirement authority. Metadata and exact batch selection must be supplied by Root's separately admitted29-batch contract. Root must bind expected_rows/directory manifests, each downloaded manifest/archive hash, helper and preservation source hashes, finite resource limits and the exclusive new destination. Batch index/selection authority is external; the helper checks its supplied start/stop slice and exact archive, not an unprovided global transport ledger.

There is no atomic filesystem snapshot or malicious concurrent namespace-writer exclusion. Descriptor/no-follow/exclusive-open/currentness checks refuse observed changes, but successful observation is not proof of absent future writers. Modes that prevent this process from reopening required files/directories can fail final readback; no permission widening or skipped hash verification is silently substituted. Archive and tree verification intentionally reread bytes; reported capacity and elapsed time remain unmeasured on the real6.9GB inventory. Actual restore, transport, final29/29 verification and any later original retirement remain Root-only work.
