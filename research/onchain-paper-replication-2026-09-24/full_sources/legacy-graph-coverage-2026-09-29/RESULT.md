# Legacy graph coverage reconstruction

Two metadata-only coverage wrappers preserve the original completed pilot02 graph
identities for January3 and June13,2022. No graph, body, source acquisition or
closed pilot was rerun. Original graph manifests and all retained files are
unchanged. The new wrappers are prospective inputs, not empirical admission.

The source-index hash matches the original admitted claim. All14 daily mapping
hashes match that index, original gate inputs and phase intent bindings. Each
week has seven contiguous source days; their declared rows sum to the completed
phase rows and graph raw count. Graph source hashes match those seven members
exactly. Raw counts equal admitted plus exclusions. The completed phase and graph
manifest hashes also match the independently retained pilot02 closure index.
The failed terminal binds the original claim and closure records verified cleanup.
All24 inspected metadata files and both new wrappers are indexed in evidence.json.

`plan_sha256` identifies the original source-index execution specification. It
must not be described as a modern graph-production plan. `source_input` is the
original admitted name `source_index`; `source_manifest_sha256` is that index's
hash. The wrapper format passes the current graph-coverage metadata validator
without creating or loading a GraphSnapshot. This establishes metadata lineage,
not fresh array-byte verification, source-vintage truth or cross-week/global
transaction-identity uniqueness.

Before empirical reuse, explicitly bind the original graph manifest, this wrapper,
the original source index and lineage evidence in a reviewed registration; perform
bounded fresh graph-store verification at actual use. No separate graph-rebuild
claim is needed merely to add this coverage metadata. Whether a particular wider
cohort has adequate cross-week validation remains a distinct admission question.

unresolved. Original109 cell dispositions are unchanged.
