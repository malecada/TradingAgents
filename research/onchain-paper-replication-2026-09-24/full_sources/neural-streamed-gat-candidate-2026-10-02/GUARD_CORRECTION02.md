`validate_result` is now the sole success/expected-RED acceptance boundary. It requires actual exact kernel memory controls, initial/final/child-terminal event counters, CPU readiness plus body affinity readback and available per-thread evidence, native file/runtime limits, cgroup/MainPID joins, stable terminal codes/statuses, verified cleanup, untruncated regular child log below4MiB, exact sampled storage policy/observation/peaks, disk floor, and the complete expected oracle phase list. RED additionally requires only the exact AssertionError RESOURCE_EDGE_WIDE_SAVED_TENSORS and the matching guard child-exit reason/failed phase. GREEN requires clean completion and no error. No missing control/event/terminal field defaults to success. Any storage_breach, storage_last_error, cleanup_error, elapsed kill, log-limit/truncation indication or missing proof rejects even if the original guard limit_reason still records the expected child assertion. Empty final CPU-thread maps are permissible only with actual body and cpu_ready affinity proofs; processes may already have exited by final sampling.

`immutable` uses bounded descriptor-relative exclusive/no-follow writes without a stream context. It captures/rejoins the original parent inode, writes all bytes, checks final file/entry identity and exact size, fsyncs the file then parent directory, and rejoins the parent again. A failed write leaves partial bytes; no identity/file is overwritten or retried. Every acquired child/parent descriptor receives exactly one close. `_close_owned` is an AST-exact copy of the independently accepted dictionary03 reducer, SHA256 c9dff424496c0ea7726a14a9816566f1db8c9be483d21e40940289e675a2ac2e. It considers all actual failures before creating an ordinary-cleanup terminal wrapper, preserving first true fatal identity and prior ordinary causes. No shared helper was edited.
