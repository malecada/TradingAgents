# Registered saved-MCM to graph tensors

The route requires the actual current OwnedJournal/FeatureJournal and a locally
issued dictionary prerequisite. It selects feature_tensor_input from both the
registered producer plan and execution job, reads the hashed policy and verifies
its exact schema. Required resident graph membership, source closure and native
int64 edges are checked before saved MCM loading. Conversion numeric allowance
is preflighted from actual node/motif/edge dimensions before calling saved.admit.
No caller-constructed MCM receipt bypasses that admission.

Actual saved admission retains exact graph/node/motif/dictionary/policy/sidecar/
event/component checks. The route then joins node order and dimensions, computes
the fixed feature identity and invokes the accepted bounded CPU tensor converter
with a combined source/metadata/graph/MCM lease. The returned immutable record
binds owner, graph, node order, full MCM provenance, selected policy, feature hash
and numeric reservation. The feature mapping prevents replacement; its tensors
remain mutable and the receipt lease checks their byte/type/device identity
before and after upstream evidence leases. This is an in-process integrity
contract, not protection against arbitrary Python modification or concurrent
adversarial mutation.

The feature policy bounds the conversion phase: source MCM+edge payload, output
tensor payloads and one validation/copy scratch chunk. The saved-admission phase
has its own selected read/copy cap. These phase caps do not count dictionary
tickets, parent graph backing stores, earlier receipts, Python/allocator memory,
model activations, physical storage or aggregate process RSS. The route retains
one saved MCM receipt as a prerequisite for subsequent evidence leases.
