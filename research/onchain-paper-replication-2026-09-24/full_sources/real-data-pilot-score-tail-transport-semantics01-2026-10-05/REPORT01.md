# Complete original score-tail streaming semantics

The candidate `score_tail_semantics.py` validates one COMPLETE original tail using stdlib only. `verify_complete(read, *, start_raw, terminal_raw, start_sha256, terminal_sha256, scope, owner)` accepts an already-open binary reader callback. A file uses `file.read`; a descriptor uses `lambda n: os.read(fd, n)`. The caller supplies separately authenticated original metadata pins, scope and owner. The helper opens, closes and rewinds nothing; it has no callback granting Owner authority.

Both metadata bodies are bounded to the original 8192 bytes and SHA-256 pinned. Exact original header/terminal fields, version/type, scope/owner, destination identity, positive cell capacity, COMPLETE status and full denominator are required. Records retain the original `<Qd32s32s` 80-byte layout: global ordinal, float64 similarity in [0,1], opaque 32-byte purpose hash and chained SHA-256. Every record is checked and contributes to the terminal whole-body hash; final chain and exact EOF are required. Original start_cell=0 and score=0 are valid; cells=0, empty/incomplete and FAILED tails are outside this complete-only API. The original verifier allows any bounded terminal reason string; that exact rule is retained rather than silently requiring an empty reason. Duplicate JSON keys are explicitly refused; the original canonical writer never emits them.

Working memory is O(80 bytes + bounded metadata). At most count*80+1 bytes are requested, with each request at most80 bytes; the original maximum is floor(8MiB/80) records. Short reads are supported, over-return/None/early EOF refused, reader exceptions propagated. A caller-owned bounded buffered reader can reduce transport syscalls. Reader deadline, descriptor stability, whole transport completion, filesystem identity and concurrency remain external: this is one streamed content pass, not the original filesystem verifier's two sampled passes or directory/lease checks.

The report explicitly denies purpose-ancestry, full-history roster, immutable storage, admission, scientific completion, capacity and deletion authority. It verifies all records of one supplied original tail; the existing transport caller must enumerate and authenticate the complete original tail roster, start ordinals/destinations, aggregate history, original matcher/purpose generation and convergence provenance. A syntactically valid purpose hash is not evidence that it came from admitted graph inputs. No codec, spool, router, score_tail, numerical method or live source was changed.

Four focused offline tests passed (actual tool99c735, exit0; raw stdout/stderr retained). Synthetic bodies were produced by executing only the unchanged original ScoreTail.append AST in an explicitly non-authoritative local file harness, plus its original stdlib encoding/identity helpers; no NumPy/torch or research authority module was imported. Cases cover exact original valid bytes, fragmented/FD reads, zero score/start, upper ordinal boundary, incomplete/failed/empty denominators, reordered/corrupted/trailing bytes, rehashed invalid ordinal/finite-score cases, wrong metadata pins/scope/schema, bound violations and propagated reader failure. These tests establish format behavior only. No retained-data computation, resource measurement, claim, native job, external transfer, recovery or deletion was performed.

Integration remains prospective: independent source review, frozen selected caller/source coverage, authenticated metadata/roster and existing bounded codec/spool transport are required. Scope and expected original hashes must never be inferred from an untrusted stream. Root owns any future live integration after the active source freeze.
