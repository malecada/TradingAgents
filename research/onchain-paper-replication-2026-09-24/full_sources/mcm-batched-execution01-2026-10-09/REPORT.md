## Numerical executor

`PairExecutor(config,policy,schedule,checkpoint)` copies the original numerical configuration, pair policy and schedule. Every pair runs original pair.policy_check, matching_checkpoint.create, advance and score_only. The nested max_checkpoints/calls_per_checkpoint/operations_per_call loops and done test follow compact_matcher.py:308-334. Long pairs invoke the supplied checkpoint callback after precisely the same group of advances and before schedule exhaustion; the callback receives purpose hash, checkpoint ordinal, actual state/graphs/config/policy. Cumulative checkpoint count and byte reservations refuse before new allocation; checkpoint attempts consume reservations before callback execution. No algorithm/RBF/arithmetic, normalization, RNG, convergence or operation-budget implementation is replaced. Engine state closes on success, advance/score/callback failure or schedule exhaustion; cleanup failure poisons and either raises or annotates the primary exception.

Checkpoint callback must actually preserve the supplied state using the existing checkpoint engine and selected policy if durable continuation is wanted. The candidate does not fabricate a checkpoint receipt, reopen checkpoints, or assert callback durability. Exclusive graph/state ownership and an unchanged numerical runtime during a call remain caller obligations. Configuration may retain all original32 motifs/512-sample/full-node settings; the executor performs no sampling or reduction.

## Bounded journal

`BatchJournal(new_root,batch_cells,max_cells,max_bytes,max_body_bytes,boundary)` creates an exclusive new namespace. `run_batch(list_of_(purpose,a,b),executor)` requires contiguous integer `purpose.ordinal` starting at the current cell cursor, at most4096 cells/batch, <=8192 encoded bytes/purpose, <=1MiB/bounded body and cumulative byte/count ceilings. It reserves two maximum bodies before work; an additional per-record metadata bound is checked before callbacks. Graph payloads remain caller-owned and are not serialized. Purpose hashes are freshly calculated; repeated numeric graphs still have distinct occurrence purposes.

One boundary callback precedes a durable exclusive pending range/ordered-hash record. Each pair then computes in order. The second boundary callback follows all numeric results. Records retain ordinal, purpose SHA256, exact big-endian float64 score bits, iteration count and convergence status. Completion is written to an exclusive temporary, fsynced, read back byte-for-byte and SHA-checked, then atomically published by exclusive hard link and directory fsync. Temporary unlink follows publication. No final filename is overwritten. All failures poison the object; descriptor close is explicit. Maximum cumulative bytes are conservatively charged on attempted writes. The same underlying temporary/final hard link does not duplicate payload blocks.

Without a verified final chunk, the entire pending range is attempted/unknown, including computed-but-unpublished prefix cells; no pending record claims completion. After atomic final publication a later cleanup failure can coexist with a complete chunk; callers must retain the failure and inspect the exact final evidence, not infer outcome solely from method return. No automatic retry/resume/retirement is provided. Byte caps cover journal bodies; caller graphs, Python allocations, directory overhead and checkpoint bodies are not covered by that cap. An exclusive trusted parent namespace is assumed; adversarial rename/replacement or arbitrary callback mutation is not certified.
