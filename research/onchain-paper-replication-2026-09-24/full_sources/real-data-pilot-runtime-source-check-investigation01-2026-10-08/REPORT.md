# Runtime source checks — source-only call trace

**Finding: the sampled generic live callback does not unconditionally redo ResearchRun admission/Git source authentication.** The full callback does. The suspected bypass of the 10-second source-check schedule is not present in this traced live chain. This is static source evidence, not runtime attribution or a claim that live checks are cheap. No source change, test, process attachment, numerical import, graph read or job was performed.

Module references below use `tradingagents/research/onchain_replication/`; lifecycle/admission are in `tradingagents/research/`. Exact source and policy pins are in PINS.json.

## Full checks and existing sampling controls

`Lease._full:106–110` calls execution.check and authenticates loaded modules against source bodies. `ImportedExecution.check` (`original_import_stage.py:163–177`) enters stage.lease → Prepared._check and performs a second Prepared._check later. Prepared._check (:74–82) invokes **bound.check**. `Binding.check:112–117` performs run._check_source, all input hashes, numerical-source Git anchors and runtime inventory. `_check_source` (`lifecycle.py:145–154`) calls admission.admit; `admission.py:236–253,292–294` checks HEAD/design/registration/charter/runtime and source files, including fresh Git bodies in `_source_files:107–135`. These are genuine full validations, unlike the generic live path.

Gate21's selected fixed13 `imported_authority_lease.json` contains live100ms, fingerprint1000ms, full10000ms, max_stale60000ms and max_calls65536. `Interval.validate:28–64` forces full on boundary, initial call, call-count exhaustion or elapsed full interval; it also rechecks full due time after live work. Full is followed by fingerprints. Live may run again after full/fingerprint work if its interval elapsed. Actual sampled callback completion times are retained; stale/clock/error cases poison the scheduler. These are not fixed-frequency timers independent of callback duration.

Mandatory boundaries include activation (Lease constructor:91), first target entry (:151–153), Target.check/final (`imported_mcm_identity.py:82–104`), score-tail seals (`mcm_score_stream.py:214–217`), stream finish (:238–241) and producer success (`compact_mcm.py:356–358`). Default no-lease Target.lease still executes full execution.check (:93–99).

`sampled_archive_evidence=True` only samples closed archive history when a history object exists and `_typed_expected` is absent (`compact_owner.py:479–489`). Otherwise evidence is full. Archive operation live uses `_current(full=False, sampled_evidence=True)` (`archive_owner_operations.py:131–146,171`); Context._outer (:339–359) checks active claim/guard/history, not source admission. Archive construction/preflight/finalization have separate source checks; those are not this per-event live route.

## Narrow conclusion

There is no legitimate “remove live Git checks” patch here: those checks already live in the full callback. The two Prepared full checks inside execution.check are separated by content/metadata work and cannot simply be collapsed as adjacent duplicates. Any future reuse would need a demonstrated callback-free authenticated interval and final mutation/revocation proof, without reducing mandatory boundary frequency. Sampling or deleting the repeated motif/inventory checks would be a different policy/semantic change, not a justified consequence of the existing source intervals. Preserve them. No implementation is proposed by this investigation.
