# Registered matching ownership candidate

This dated component connects an actual active ResearchRun to one explicitly
selected fit representation producer, its registered pair policy and descriptor,
its existing FeatureJournal ownership records, and its live guarded worker.
It does not allocate pairs, load graph/array bodies, route dictionary/MCM work,
or authorize empirical execution. The maintained package is unchanged.

The prospective producer plan explicitly uses schema version2 and a
pair_checkpoint_input. The descriptor includes the complete numerical backend
identity and exact policy input hash; cache identity therefore changes explicitly.
The candidate refuses the previous implicit score_only route, a different selected
producer, completed reuse, a foreign journal, terminal ownership, any parent and
any sibling attempt. Current production consumers do not yet accept this new
contract; introducing it here is not a registration or default change.

The binding records the actual execution source commit, claim hash and
registration hash. Separately, the numerical context may name an older committed
source anchor only after all83 current execution-package source files match its
committed bytes, admitted current hashes and the locally imported implementation
source tree. The candidate itself must also be an admitted source. This is strict
byte compatibility, not an assertion that changed implementations are equivalent.
The runtime identity hashes the admitted environment inventory, including the
lockfile, package versions, Torch and CUDA information. CPU/environment changes
are not silently considered compatible. Numerical policy fields are all explicit
positive integer bounds; shape-specific validation remains PairSession's job.

The existing guard checker validates the current process's cgroup, kernel limits,
CPU affinity, command, current boot and lease. This component additionally joins
the registered resource values and run experiment/source to retained launch and
owner metadata and the live monitor identity. Compact ownership metadata is read
with a64KiB bound, same-device regular-file checks, O_NOFOLLOW and before/after
stat signatures excluding access time. Reading can legitimately update access
time; the first implementation incorrectly rejected that and is retained.

check() re-admits current source, checks all registered input bytes and runtime,
and checks the active claim, journal ownership and live guard. lease() performs
only the latter inexpensive ownership/guard checks. Neither is a process lock or
a permanent execution permit. The outer source freeze and sole writer remain
required. Later consumers must call the appropriate check at execution and
publication boundaries. A frozen record/context prevents accidental mutation.

Tests use actual tiny Git registrations and ResearchRun lifecycle claims in
temporary directories. Only the kernel guard assertion boundary is replaced by a
synthetic receipt; one negative also simulates monitor death. These tests establish
binding behavior, not kernel dispatch or live empirical feasibility. No real
registration, retained body or historical job is executed by the tests.

Outstanding integration includes actual registered workload membership, exact
failed-owner/observer death and full ancestry admission, bounded orphan handling,
ancestor-inclusive workflow quota enforcement, and dictionary/MCM checkpoint
routing with directional-distance/RNG and partial-row parity tests. The first-owner
restriction must remain until continuation is implemented and reviewed. A fresh
source gate and appropriate verification are required before production release.
