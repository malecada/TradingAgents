## Main conclusion

The intended scientific architecture is implemented: training-only neighborhood sampling and motif dictionary, fixed motif similarity MCM, trainable MLP, directed GAT, mean pooling, price-joined LSTM with additive temporal attention, and separate regression/classification heads. Current resource integration also uses the actual batch factory and original model/optimizer configuration. This is substantially more than a skeleton, but it is not an empirically completed paper replication. Whole real MCM generation, real joint neural training, full-fold financial fits, matched Tables 1–6 results and exact original-data reproduction remain unproved.

Pilot35 provides evidence of an actual imported dictionary followed by failure before the first MCM batch; its original summary has zero complete graphs, one failed target, six unavailable targets, training null and zero financial fits. It does not demonstrate native matching throughput or a model update. Pilot34 retained nine partial numeric summaries covering 36,864 of 415,968,128 cells, not a complete graph. Separately, native03's accepted engineering outcome reports 130 equal boundary states and 147 native chunks in finite synthetic cases. These three evidence scopes must remain distinct.

## Actionable findings

**F1 — Confirmed operational blocker, not an observed scientific arithmetic error.** `compact_mcm_batched.py:550–553` performs the two compiled-policy input constructions between the second successful added lease boundary and the failing third one. These constructors perform ten `ResearchRun.read_input` calls; `tradingagents/research/lifecycle.py:145–168` freshly re-admits source for each. The actual traceback reaches the scheduler's initial freshness test before a new callback can refresh it. No direct `graph_hash` call occurs between these two boundaries. The retained phase totals do not measure individual reads or prove their cost share. See the separately frozen stale35 finding for the exact trace and limits. Plan: obtain phase-level source/admission/hash/compile durations and remove redundant work only under an explicit detection contract; never silently cache mutable authority validation or increase the 60-second threshold to hide the gap.

**F2 — Definite failure-reporting vulnerability in the general financial trainer.** `training.py:96–98` formats the primary exception and writes `failed.json` before bare re-raise, without shielding either operation. `evaluation.py:136–138` repeats this pattern, and its SVM branch at 119–122 similarly writes multiple failure markers. A disk-full/permission/fsync failure, or exception whose string conversion raises, can replace the actual training failure; a fit may retain its claim/checkpoint without its required terminal marker. This is a source-demonstrable exception path, not an observed cause of pilot35. Before financial use, latch the primary exception, make each reporting/cleanup action independently best-effort, retain secondary failures separately, and re-raise the original. Test a single failed batch with failing formatting, failed publication and a retained checkpoint; no financial rerun is needed to establish this property.

**F3 — Checkpoint cadence is a safe-point target, not a hard wall-time loss bound.** `training.py:75–92` checks the 600-second interval only after a complete forward/backward/optimizer batch. Dictionary checkpoints similarly occur after completed pair work (`dictionary.py:68–74`). A single long batch can exceed 600 seconds with no resumable update state. This does not show incorrect resumed arithmetic, and does not justify saving a half-applied optimizer update. Document the largest noninterruptible unit and measured maximum safe-point interval; retain exact batch cursor/model/optimizer/RNG atomicity. If the budget requires a hard limit, qualify a narrower checkpointable computation boundary before claiming it, rather than changing the wording to imply a guarantee.

**F4 — Current scientific status is spread across incompatible ages of documentation.** Canonical `fidelity.json` still labels all target implementations pending; `implementation-coverage-v4.json` records implemented synthetic components; `completion-interim-11.json` is a September checkpoint with 25/52 accounting; `PROTOCOL.md` has historical resource limits that are not pilot35's current gate. These historical records must remain immutable, but readers need one dated current applicability index mapping every F/C requirement to source, evidence and unresolved limitation. Stale documents are not grounds to silently alter the executable gate. The audit also found `streamed_gat.py:1` still describes a prospective module despite its explicit selection in `model.py:34–36`.

**F5 — Definite evidence gap: selected backend does not establish use or speed.** The numeric summary records policy selection but does not expose actual native invocation/chunk/fallback counters. Current batch elapsed fields cover numeric memo-call work and exclude other phases; they are not full wall-time or pure-kernel timing. The installed native03 qualification proves its finite cases only. Add bounded, explicitly scoped hit/fallback/progress telemetry at the existing execution seam before making a real-workload acceleration claim. Existing telemetry investigation identifies exact available fields; no new generic profiler is needed.

No current label-leakage, wrong regression tensor-shape, detached GAT gradient or cross-update embedding-cache defect was established by this source audit. That is a bounded negative finding, not a complete correctness certificate. Actual label rows, full raw coverage and financial checkpoint bodies were deliberately not reopened.

## Data, clocks, labels and populations

`dataset.py:69–105` checks asset membership, unique daily prices, strictly positive finite prices, Monday-aligned complete seven-day graphs, graph availability at least one day after week end, exact expected graph per time step, training-label purge at test start and test-label boundaries. Input dates precede decision time; the target is that day's represented closing price, and direction is strictly greater than the previous close (ties map down). The latest input price is assumed available at decision midnight. `fit_scaler` at 108–114 uses only distinct input dates from eligible training examples inside the training interval; it does not fit on test prices or all target values. Regression targets use the same scalar transform and predictions are inverted (`evaluation.py:25–28,103,126`). Source semantics are coherent with the frozen clock convention.

That clock is not proof of historical vendor availability. `coinmetrics_prices.py:19–29` explicitly admits retrospective PriceUSD with next-midnight availability assumed and original-paper/historical publication identity unverified. The provider revision is pinned and missing values are not blended or filled. This is a declared deviation, so results would be retrospective predictive research under an assumed clock, not demonstrated historical tradability. Original Yahoo source failures remain evidence.

`population_assembly.py:18–135` requires the full expected weekly denominator, exact complete/unavailable dispositions, source/config/calendar/fold/price commitments, complete decision-count reconciliation and separate array verification. Metadata assembly does not authenticate array bodies itself. The actual pilot intentionally uses `real_pilot_population.py:83–108`: sixteen fixed consecutive eligible decisions, seven complete graph roles, a subset train hash and a subset scaler. Its `full_fold_population=false`, `full_fold_scaler=false`, and `paper_financial_fits=0` flags are essential and must survive reporting. The current wrapper's `real_pilot_import_caller.py:565–607` requires all seven full MCMs before using the actual `batch_factory` and one-update trainer.

ETH `weekly.py:38–91` deduplicates transaction identities before admission filtering, aggregates directed count/value edges in fixed order, retains exclusion counts, and stores log1p features with underlying aggregate values. The ETH float-value convention is an explicit approximation, not exact wei conservation. BTC `btc_weekly.py` uses exact Fraction projection and tracks prevouts/duplicates/chain order, fees and unsupported-transaction dispositions before converting feature values. Those are graph-projection transaction fees, not an investment strategy's execution-cost model. These implementations and retained synthetic checks do not substitute for full raw-to-graph denominator reconciliation for both assets/history.

The Task1 source audit and declared decisions remain controlling: the original full source/configuration and historical fund cohort were not recovered. The referenced author repository does not provide the complete MCM implementation. Original 65-fund/25-Alameda population and vintage limitations remain paper-scope blockers; no convenient modern cohort should replace them.
