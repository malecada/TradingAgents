## CH1 — High: authenticated old evidence is silently recaptured as a new baseline

**Location:** candidate `compact_cold_features.py:195,212–216`; `Authority.check:97–117`.

The factory captures original evidence at line 195 and verifies that snapshot at line 212, after the final original terminal check. It then publishes handoff metadata and the registered output, and line 215 captures the old roots again together with the new handoff root. The second snapshot replaces the first without proving that every original file signature/hash and directory/member tuple is unchanged. `Authority.check` verifies this replacement snapshot, not the original `record['file_pins']` and `record['directory_pins']`. Those original pins are retained as prose/evidence data but are never joined to the authority's replacement snapshot.

Concrete counterexample: a `failed.json` is added to the original `onchain_compact_terminals/<workflow>/<experiment>` directory between line 212 and line 215, including during the output-publication boundary. The second scan records the extra failure file as expected inventory. Subsequent namespace checks compare only existence, the new snapshot accepts its own membership, numeric-map validation checks graph components, and full stage verification checks stage contracts rather than the original compact-terminal directory's status. The old terminal's rejection of an unexpected failure file is never called again. The detached authority can therefore accept conflicting terminal failure evidence. A modified sampler/publication file can similarly be accepted into the new baseline where no later semantic reader independently checks its old hash.

The new handoff `start.json`/`complete.json` bodies also need explicit expected-body joins: the second scan currently blesses whatever bytes exist when captured rather than verifying those files against the actual bodies just published.

**Required correction:** add only the newly published handoff root to the authority. Require exact equality of the replacement snapshot's old-root subset against the original authenticated snapshot, including file membership/signatures/hashes and directory identity/membership. Bind the new files to their expected encoded bodies and exact inode. Repeat the original-subset check after publication and before retiring original checks; do not overwrite historical pins. Retain conflict/failure evidence and reject the handoff. A focused counterexample must inject the late failed marker and old-body mutation at the actual boundary, plus changed newly published receipt bytes; each must refuse, with no mint/fallback. This review does not claim an atomic filesystem snapshot, but it requires that sampled checks compare against the authenticated version rather than silently adopting a changed version.

## CH2 — High: ordinary claimed handoff failure loses the enclosing fail-stop disposition

**Location:** candidate `compact_native_producer.py:144–157`; candidate `job_payload.py:205–223`.

The new `handoff_started` branch poisons the original owner and re-raises the original exception unchanged. An ordinary `ValueError`, `RuntimeError` or `OSError` from handoff creation or its immediate `finalize()` therefore reaches the payload's generic representation-error handler. That handler writes a failed/unavailable representation result and continues preparing/fitting the remaining batch. The explicit fail-stop branch above it recognizes `CompactProducerError`, not these raw exceptions. A claimed handoff failure can consequently be reduced to an unavailable representation; the outer job can continue and potentially complete its unavailable-cell ledger. Preserving partial metadata is necessary but does not make that disposition correct.

**Required correction:** ordinary failures after entering the handoff must propagate through a dedicated explicitly caught enclosing-job failure type, or the existing `CompactProducerError` route. Preserve the first fatal exception object (including `MemoryError`, `RecursionError`, `SystemExit` and interruption) and all failed evidence; do not indiscriminately wrap fatal errors. Avoid reopening or falling back to the old resident route. Exercise the actual extracted producer/caller exception path with a handoff `ValueError` and a post-handoff finalization `OSError`, proving that no `execute_batch` call or successful outer completion follows. Include fatal-identity and failed-marker/cleanup failure cases. Merely asserting that a `raise` statement exists is insufficient.

## CH3 — Medium: detached guard drops an existing monitor-identity join

The detached guard checks `live['owner_identity']`, policy fields and liveness of the captured owner PID/start ticks, but omits the original check that the live guard receipt's top-level `monitor_pid` is an actual integer equal to `owner['monitor_pid']`. `resources.assert_guarded_worker` does not restore that join. A receipt with the original owner identity but a conflicting top-level monitor PID is accepted by the new guard while rejected by the original Binding guard.

**Required correction:** preserve the exact integer/equality join as well as PID/start-tick liveness. Add a narrowly extracted guard counterexample for a differing PID and for boolean PID values; exact matching evidence remains required. A detached authority should not weaken an existing parent-monitor binding while retiring the original Binding callback.

## CH4 — Medium: newly reserved handoff directory is not made durably reachable

**Location:** candidate `compact_cold_features.py:209–213`; `cold_files.write_once:114–122`.

`durable_mkdir(directory.parent)` durably creates missing ancestors, then `directory.mkdir()` reserves the handoff directory without fsyncing its parent. `write_once` fsyncs the file and the new handoff directory, not the directory containing its newly created name. The subsequent registered output may therefore become durable while a crash loses the reserved handoff directory entry and its evidence. The existing original terminal path explicitly synchronizes its parent after exclusive child creation; this candidate omits that step.

**Required correction:** durably publish the exclusive directory entry through a held, verified parent descriptor before publishing handoff files/output. Preserve inode/path checks, partial reservation evidence and the first fatal error on parent-open/fsync/close failure. Test operation ordering and injected parent-sync failure; do not delete/recreate the failed attempt. This is an evidence-durability requirement, not a claim that filesystem fsync removes all hardware failure risks.
