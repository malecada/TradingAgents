# Saved graph verification

This is read-only closure verification of terminal
`eth-paper-graph-resource-20260930-05`, not a new source transform, financial
experiment, sample or retry. The eight terminal cells and spent allowance remain
unchanged. No raw file, retained SQLite database, price or label is opened.

Before execution, independently review `verify.py` and bind its hash and the
terminal, graph manifest, coverage and guard receipt hashes. Execute once with
the pinned interpreter under the existing resource guard: 3 GiB memory.max,
2 GiB memory.high, zero swap, two-CPU affinity, 3 GiB host reserve, 6 GiB startup
available memory, 10 GiB disk floor and 1,800 seconds maximum. Preserve any
failure and exclusive started receipt; do not overwrite or repeat that identity.

Verification reads all five array files and checks their bytes and SHA-256,
independently reconstructs canonical graph JSON identity, checks numeric types,
dimensions, finite attributes, sorted unique node identities and directed pairs,
endpoint bounds, positive integer edge counts summing to admitted transactions,
edge log1p transforms, and independently recomputes four node features using
bincount. Float comparisons use the existing 1e-12 relative/absolute tolerance.
Coverage checks bind the claim, manifest, configuration, contiguous seven-day
interval, daily receipts, declared source hashes and complete row denominator.

Raw transaction uniqueness, raw value correctness and exclusion classification
remain producer evidence. The verifier cannot independently establish them from
saved arrays. A passing result is not full Task 8 completion, permission to fit,
proof of GPU feasibility, or proof of off-device graph recovery.

No production loader, validator, graph hash or feature construction routine is
called. Standard JSON encodes each saved row/scalar for an independent identity
calculation. One long edge-index row is temporarily converted to a Python list;
the finite guard includes that allocation and file cache.

The verifier algorithm is copied unchanged from the accepted prior graph check; only the target identity, week boundaries, availability date and declared raw count change. All five new arrays are covered; the old graph verification identity is never rerun.

This preparation was created while graph05 was active. It must not execute until
the actual complete terminal, owner/cgroup cleanup and independent compact review
exist. No bindings.json or prospective array hashes are invented; bind actual
closure evidence only after publication and review. Do not launch concurrently
with the graph producer. Fresh resources and absent verifier identity are required.
