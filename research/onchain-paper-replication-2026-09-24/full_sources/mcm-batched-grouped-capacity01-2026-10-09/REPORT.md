# Conditional grouped capacity calculation

`calculate.py` emits exact seven-graph counts and conditional source-derived byte envelopes in CAPACITY01.json. It imports only stdlib, reads metadata/source hashes, and creates no authority objects, graph arrays or transport operations. TEST01 is retained; TEST02 reruns the same calculation with explicit256MiB address-space,4MiB file,30CPU-second and two-CPU bounds. No current free-space observation or admission is claimed.

The original12,999,004 rows and415,968,128 cells produce101,559 batches and **6,352 groups**, calculated separately per graph. This requires12,704 typed operations,19,056 typed chunk credits,31,760 actual successful commands and76,224 policy command reservations. Successful retained inventories contain88,935 work files,44,485 work directories and57,168 typed ledger files. Every per-graph policy minimum is emitted, including21G+4 work entries,2G operations,3G chunks,12G commands,32G anchor memory and168B original token bytes.

The USTAR ceiling uses1024B pending and complete bodies and exact53-byte records plus92-byte header, preserving every original cell. Total group archives are bounded by22,488,330,240B; preservation requires this amount, two recovery passes44,976,660,480B, and the existing shared logical transport charging requires89,953,320,960B before old transport allowances. These are conditional ceilings, not observed archive sizes. Maximum live original group payload is3,507,648B; add up to three4MiB archive copies and filesystem allocation, controls and failure headroom. Seven per-graph maxima summed in the totals are not a simultaneous scratch requirement.

Specific metadata bounds are computed with the actual emitter field layouts,48-member manifests and up to5376 token-hex characters. The envelope requires safe ASCII paths<=512B, input names<=128B, nonnegative signed63-bit integer fields, and source-selected1024B journal metadata. These are **future entry constraints requiring actual checks**, not guarantees inferred from canonicality. Encoded shape variables are used only to count lengths; no synthetic receipts are persisted or treated as evidence. The full-group manifest is<=59,313B, offload record<=67,337B, and largest typed body<=7,539B. This avoids multiplying131,072B by every work file. Actual paths/names outside these bounds invalidate this calculation.

Successful work bodies total<=962,598,737B (1,222,254,592B rounded per-file to4KiB); typed bodies<=203,534,275B (338,149,376B rounded). Exact9-byte origins,8192B-per-batch summaries, original token files, both original spool and published4-byte matrices, and those controls total **9,480,953,856B** conditional persistent file allocation. Directory allocation/inode metadata are excluded and must be measured/reserved; rounding is an assumption requiring the target filesystem's actual block/frsize behavior. Sparse/compressed/shared-block savings receive no credit. Group anchors203,264B and remaining original token/cache/RAM costs remain separate.

This is not whole-capacity approval. Adding the10GiB floor alone requires20,218,372,096B. The inherited24,828,579,840B availability is an old sample, not current capacity. Original graph/index/tail/feature/model stores, current other-writer reservations, failure receipts, dispatch controls, checkpoint allocation and runtime staging still need a single physical-store join. The existing checkpoint reservation43,058,298,880B and160 checkpoint count must be explicitly reconciled with actual retained layout/schedule and shared caps; it cannot be silently zeroed or treated as free disk. Charging that entire allowance physically already exceeds the old availability.

Unchanged legacy dispatch formulas imply a large additional control reservation (exact values emitted). A selected compact control-history policy needs its own file/shard/diagnostic bound; the calculator does not substitute it implicitly. Typed context additionally publishes two claims per group, separate from the nine ledger files. The typed ledger retains expected raw bytes and digest/name maps in memory;203,534,275B is a success-body **envelope**, not a measured RSS or guaranteed lower bound. Dict/key/bytes overhead, duplicate claims, legacy entries and repeated full-history audits remain costs. The source's audit frequency has not been changed or benchmarked.

Root must verify the encoded constraints and whole local/remote capacity, preserve all legacy allowances, reserve failure/control/scratch/RAM, and bind the actual current grouped source closure before any empirical launch. No originals or numerical methods were changed.
