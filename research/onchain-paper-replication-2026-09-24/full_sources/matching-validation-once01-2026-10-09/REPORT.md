# Same-call graph validation reuse — source-only candidate

Two-module candidate; Main/native23/Git remain untouched. matching_identity factors the original attributed identity encoding into a private already-validated helper; the public entry still performs exactly its original validation. matching_annealing.check keeps its original first validate_pair and only uses the helper at the original identity-comparison position. Fresh framing/graph byte hashing and configuration hashing remain unchanged, as do every state/numeric check, arithmetic/RNG operation, checkpoint schema and publication schedule. No result, compiled code or currentness boolean is cached across calls.

Eligibility is exact AttributedGraph with exact tuple/plain-string identities and all three arrays read-only through a bounded ndarray base chain to immutable bytes, exact plain dict state/config and primitive config values, original pair validator/code, original graph validator/code and function binding in both caller modules, original graph identity/code and ann.identity. Unsupported mutable arrays, subclasses, altered pair validator or dict subclasses retain original identity route. Source/runtime authority remains the existing external frozen-runtime contract; arbitrary mutation of function dependencies, tracing hooks or graph internals during a call is outside this exclusive immutable domain. An observational profiling hook was used to count calls; it did not mutate runtime objects.

Regression: actual baseline source invokes validate_attributed four times per check (twice each graph); admitted candidate invokes it twice. The removed calls duplicate endpoint extrema, node/edge uniqueness and finite-feature scans. Original identity hashing still reads every graph array on every call. This establishes removed work, not measured wall-time improvement or population capacity.

Final focused TEST03 PASS: seven bitwise V/M/Q/metadata boundaries across operation budgets, checkpoint loading in both directions, fresh-identity mismatch after valid immutable-feature replacement, invalid graph/config failure precedence, and mutable graph/subclass/pair-validator/config-dict/state-dict fallback. Public identity bytes agree. TEST01 also passed before tighter plain-dict guards. TEST02 failed only because the existing exclusive checkpoint fixture directory was reused; its traceback is preserved. TEST03 used fresh names and tested the final source. No old broad matrix or benchmark was run.

No admitted-domain scientific exception is intentionally moved: initial validation remains first; string/array encoding checks and mismatch checks remain in original order. Removed duplicate validation cannot independently fail on unchanged valid admitted graphs. Timing and allocation boundaries necessarily differ (fewer validation allocations, extra cheap guard operations); no universal MemoryError/asynchronous-exception equivalence is claimed. Unsupported inputs retain original validation, though the added nonmutating eligibility checks introduce their own resource-failure possibilities. Malicious/custom state field values or in-place function/global mutation outside the frozen runtime are not certified.

Checks used pinned .venv/bin/python -B, timeout30s, AS256MiB, FSIZE4MiB, affinity[0,1] (two logical CPUs, not isolated), nice10 and numerical thread1. Only tiny synthetic arrays were created; no original/empirical graphs or labels read, no native job or registration. Exact baselines, candidates, forward/inverse diffs, source test files and receipts are retained and hashed by MANIFEST.json. Root reviews and integrates independently.
