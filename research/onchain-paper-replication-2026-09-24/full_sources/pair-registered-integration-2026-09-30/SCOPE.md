the accepted maintained ResearchRun/Binding/failed-owner admission with the
accepted isolated serial pair, journal, extent and ordered workload components.

synthetic numerical work, start actual ResearchRun claims, fail the first run,

unchanged. Ordinary fixtures intentionally simulate kernel guard/death

## Remaining boundaries

The inherited owner fixture retains its placeholder required-graph hash; the
actual tiny workload graphs are separately constructed. Thus the fixture does
not establish graph/sample membership in the registered representation.
The fixture itself routes the pair root and parent reference. Production code
must still join every pair-journal owner/reference to the admitted failed
representation chain, bind exact workload/configuration/schedule/source inputs,
and reject foreign, omitted or rolled-back pair ancestors before allocation.
The harness does not provide that production gate. Its imported isolated
helpers are engineering dependencies, not an empirically admitted source
closure. Passing this harness cannot license empirical execution.

Physical whole-workflow accounting, partial/orphan artifact reconciliation,
bounded scalable journal indexing, complete representation reuse without pair
API entry and mapped full-graph MCM production remain outstanding. No physical
quota claim follows from inherited logical reservations. No real graph bodies,
resource pilots, financial fits, historical claims or research budget are used
or changed. Both assets, full history, comparisons and all 1420 planned fits
remain in scope.

The current successor lease revalidates ancestry and committed source repeatedly
at pair boundaries. This deliberate integration configuration is not a scalable
performance claim. Future bounded verification must preserve changed-source,
changed-input, changed-ancestor and live-predecessor refusals; disabling those
checks to improve throughput is not admitted by this fixture.
