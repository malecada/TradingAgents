# Registered complete date denominator

This adapter joins the accepted pure date validator to an actual admitted current
pair owner and workload. Both registered plan producer and execution job must
select the same denominator policy. That policy references registered calendar
and source-coverage metadata; the maintained calendar builder reconstructs every
Fold field and member hash. The caller Fold must match both that reconstruction
and the admitted workload descriptor. The complete ExampleManifest hash comes
from the registered workload control, not a caller-provided replacement.

The actual resident GraphSnapshot population is rehashed and converted only to
calendar metadata. The pure validator checks its exact population/required union,
full daily included/excluded denominator and every per-input graph clock using
the registered calendar lookback. No graph feature array is loaded or model fit
started. Receipt leases retain source/policy/owner, graph population/object/hash,
full example and Fold checks. Receipt attributes and nested records are immutable
under ordinary assignment; consumers must call the real admission and lease path,
not treat an arbitrary caller-constructed Receipt as an issued capability.

The adapter exposes the saved graph route's actual ownership class so the next
representation composition can use the same current owner. Ancestor/historical
admission, mapped graph populations, graph completion receipts and top-level
representation publication/reuse remain separate. Coverage metadata is bound,
not proof of complete market data. Price values, labels and price exclusions are
not independently reconstructed; the receipt explicitly retains the validator's
false price-revalidation flag and graph_completion_validated false. Calendar-day
limits do not bound all already resident objects, hash serialization, graph body
rehashing, total memory or process RSS. Existing source and policy checks remain
expensive; no cheaper lease claim is made.

The new tiny fixture uses five daily decisions, two weekly resident graphs and
a two-day lookback solely for engineering. It uses the maintained example builder
without the historical fixture's intentional truncation. The paper's 28-day
configuration is unchanged. Real temporary committed registration, ResearchRun,
feature claim, workload and pair owner are used; only the kernel guard observation
is synthetic. No sampling, matching, financial data, budget or financial fit is
consumed. The old fixture files and closed jobs remain unchanged.
