## Scope and authentication

The original registered claim is read by the same original_dictionary reader/parser. The exact historical commit and claim source equality, exact 26-entry source map, sorted names and admitted SHA-256 values remain required. Each positive blob extent remains at most 2 MiB, with 4 MiB total content; the new parser authenticates every complete body in order and refuses missing/non-blob records, invalid or oversized framing, invalid extent, missing delimiter, truncation, wrong content hash and trailing records. Binary newline/NUL content is length-framed correctly. Header object IDs are syntax checked, while the admitted SHA-256 authenticates body identity; this does not create a substitute authority. CR and NUL source-path rejection is an explicit framing restriction in addition to prior LF rejection.

One fresh `git cat-file --batch` process replaces the 26 size queries and 26 body queries on each invocation. There is no cross-call cache. Existing admission/Owner batching, current-source and runtime checks, numerical code, dictionary validation and matching hotpath are unchanged by the proposed delta. This candidate therefore supports no matching-hotpath speed claim.

Stdout, stderr, request, member and aggregate bounds are explicit. Selectors multiplex partial nonblocking reads and writes. A nonzero process status and incomplete response cannot return authenticated rows. Cleanup attempts stop, reap, stdin/stdout/stderr closure and selector closure independently. Stdin is marked released before close so it is not retried following an uncertain close.

## Explicit operational qualifications

The deadline is ten seconds for the batch read/wait loop, followed by bounded cleanup waits. It is stricter than the old ten seconds per subprocess but is not a hard whole-invocation limit; process creation and cleanup are outside that guarantee. A real timeout, forced termination, interrupted Popen construction or unusual OS close failure was not exercised in this review. Transport doubles cover the declared failure cases, not every possible native resource outcome.

The output bytearray and its final bytes conversion coexist transiently, roughly twice the wire bound plus overallocation, chunks, stderr/request storage. Subsequent parsing retains the wire bytes while hashing memoryview slices. This increases transient aggregate storage versus one-body-at-a-time reads. No measured memory-saving, timing, speed or whole-run capacity claim follows.

The pinned owned_io `_cleanup` reducer (`09d1fbcc03f2c9303db95f34ca6c07ddb47bfdb49b35452f4cb6829a5d667aeb`) defines fatal selection as MemoryError or non-Exception BaseException, excluding CleanupFailure. It does **not** classify RecursionError as fatal. An independent counterexample confirms that primary RecursionError plus cleanup OSError produces fail-stop CleanupFailure with both original error objects retained in `failures`, rather than preserving the RecursionError as the top-level exception. Source acceptance is qualified accordingly; the candidate's broad phrase “first actual fatal” must not be read as universal exception-identity preservation. There is no successful return or ordinary-unavailable downgrade in this case. If a future release requires top-level RecursionError preservation, it needs a separately prepared/reviewed reducer or narrow wrapper correction before adoption. MemoryError identity preservation with later close failure is covered by the existing actual-source test. The coordinator was notified of this limitation.
