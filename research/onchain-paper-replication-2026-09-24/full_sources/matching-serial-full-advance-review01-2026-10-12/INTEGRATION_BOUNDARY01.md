# Existing serial advance integration boundary

The existing ordinary path is PairExecutor.compute → ImmutablePairSession.advance → matching_checkpoint._advance_owned → matching_annealing._advance_checked. PairExecutor performs authority polling before each bounded advance, accounts the actual returned operation count, records the full abandoned operation allowance on a failed call, and applies the existing checkpoint schedule. A new implementation cannot convert one authorized call into an unbounded whole-pair run or move those callback/checkpoint boundaries.

ImmutablePairSession.check currently rejoins immutable graph objects/base bytes/headers, configuration and live source/function/runtime identities before the owned numerical body. A serial helper must remain a numerical implementation under these joins, not become a new source/Owner/admission authority. Fresh direct-call validation and genuine source-selected Session validation are different entry contracts; synthetic direct entry cannot stand in for the latter.

The smallest prospective numerical call seam is the annealing stage of matching_checkpoint._advance_owned. It must return the same bounded used count and valid annealing phase/cursor/iteration/beta/matrices. The existing matrix digest, hardening construction, readonly-M transition and subsequent hardening calls remain outside the helper, in their original order. A call that exhausts its allowance exactly at an outer/edge/normalization boundary must not silently perform the next operation or skip a scheduled handoff.

Eligibility checks must finish before the first mutable-state write. A refusal before mutation may use the existing route; any failure after mutation requires an explicit, trustworthy operation prefix and poisoning contract rather than silent fallback. Allocation failure, native status failure and asynchronous interruption require separate treatment. A Python numerical comparator cannot establish actual native interruption atomicity.

For genuine integration, an explicit source/config selector must pass through the existing NumericExecution → NumericReuseExecutor → PairExecutor → Session chain. The source roster and required source digests, helper function/code identities and actual native/runtime artifact provenance must be covered by existing currentness checks before use. Owned scratch allocation must be charged before allocation using the existing per-graph and whole-pilot numeric reservations, remain bounded per live pair, be disjoint from input and mutable state arrays, and be released on constructor failure, advance failure and explicit close. No generic callback, success cache or new authority framework is needed.

This is source orientation only. The candidate implementation, numerical equality, actual runtime ownership, memory fit, registration and empirical entry are not accepted by this note.
