# Read-only integration boundary — bounded restart retention

This is a source-backed handoff, not integration acceptance or execution admission. The reviewed standalone candidate05 still has RRP1–RRP4 open in the adjacent primitive review. Integration implementation should start only from its corrected accepted snapshot. No source, registration or tests were changed and no numerical work was run for this note.

The smallest useful complete route is **the explicitly selected archived-event producer only**, from actual sample Proof/dictionary through matching, reserved archive read, new stage seal and original terminal content checks. Leave the current local route and current archived full-checkpoint format strict. Do not add an optional “missing checkpoint is acceptable” flag to their readers.

## Exact interfaces that do not yet compose

`compact_matcher.CompactMatcher._save` currently owns a global progress-event directory returned by `PairLog.checkpoint_path`: `checkpoints/event-<12digit global event>`. It saves engine state, publishes intent/wrapper bytes, appends `log.progress(wrapper_sha)`, and checks the original exact168-byte frame before returning. `__call__` independently appends durable begin before engine creation, advances the unchanged operations/calls cadence, closes actual engine state, then appends and checks completion before returning a score. Retirement must not move those scientific boundaries, skip actual engine cleanup, force an extra checkpoint, or acknowledge a score earlier.

`restart_retention.Store` is not a drop-in `_save` replacement. It uses standalone JSON `EventRef`, pair-relative event ordinal `generation+1`, and annealing numeric identity `{left,right,configuration}`. PairLog frames use a global event ordinal, a separate pair ordinal, purpose SHA and the digest of the fuller `matching_pair` identity. A new versioned bridge must join all of these, including log start SHA, exact raw frame/head, and the store's externally anchored claim/progress/terminal. Neither ordinal nor identity can be substituted for the other.

Avoid a circular hash design: a frame's artifact must commit to a pre-event immutable snapshot/bridge descriptor. A later progress proof may bind that frame and its descriptor, but the frame cannot hash a proof which itself includes the same frame hash. Retained JSON bridge metadata is one possible encoding; it needs an explicit schema, bounded reservation and direct bytewise join to the actual verified binary frame. It is not enough to construct a look-alike JSON event after the fact.

The existing binary PairLog/ArchivePairLog codec can remain unchanged if its progress artifact field commits to that new descriptor under an explicitly selected stage format. The new reader then interprets the new artifact according to that format. Actual frame readback must precede scratch retirement, and the current durable anchor must still match after the last external callback. Archived rollover can remove a previous local chunk; a reader bridge cannot assume every original local chunk path remains readable forever. It must join the actual archived frame during the one reserved read and retain an anchored local proof for later content checks.

## Stage-scale accounting and replay

Do not instantiate one Store for every comparison. That would restore potentially577,498,112 per-pair directories and claim/terminal records even when no progress snapshot occurs. A bounded minimal integration can instantiate a one-pair Store lazily on the first scheduled progress snapshot. The number of such stores is then bounded by actual progress events and the precommitted stage progress cap. Pairs completing without a snapshot remain in the existing begin/complete event denominator; only the bounded selected replay set needs an explicit no-checkpoint replay disposition.

Per-pair Store caps do not constitute a stage cap. A stage controller must reserve before store creation and snapshot allocation: store claim/failure/terminal controls; cumulative generations and serialized bytes; retained engine manifests/bridge/progress/retirement records; selected replay copies; surviving failure allowance; and current+candidate saved payload for the one active pair. Counters never reset/refund between pairs. No giant in-memory dictionary of all completed pairs is needed; ordered bounded metadata can be replayed against the event population.

`compact_policy.validate` presently requires every allowed checkpoint body in `schedule.max_total_checkpoint_bytes` and adds that amount to retained logical reservation. `Owner._begin` uses that total plus stage metadata. Separate the new variant's **cumulative write budget** from **live/retained logical allowance** explicitly; do not reinterpret or lower old-policy fields silently. Original operations_per_call, calls_per_checkpoint, max_checkpoints and iteration bounds remain unchanged. Archive reference budget still depends on the full max_total_checkpoints, not only two active bodies. `archive_owner_policy._record` currently budgets40bytes per progress reference and finite read metadata: if the new reference/result encoding grows, its derived budget must change before claim; a count-preserving40-byte reference may avoid changing that component.

Dictionary capacity is not an exact realized occurrence denominator. Keep registered `capacity-with-exact-completion-v1` and actual complete-log count; reuse can produce20actual versus22capacity. Bind replay initial eligible pair IDs before distances, then join their actual first occurrences and hierarchy purpose hashes. Never choose “last” by capacity minus one or by an observed favorable result. MCM remains exact center-major/motif-major `N*K`, with selection of its fixed endpoints. Copy/verify the selected first scheduled checkpoint before any retirement of its generation. If completion happens before that cadence, retain the exact no-checkpoint disposition and full required replay inputs without forcing extra matching work.

## Smallest coherent ownership

One integration owner should hold the following linked changes; splitting them into separately enabled partial routes would create an unsafe interval:

- New stage-level retention bridge/controller/reader module using the accepted Store; its new tests/evidence. This owns binary/JSON joins, lazy stores, aggregate counters, replay selector binding and aggregate content proof.
- `compact_matcher.py`: explicitly selected snapshot/completion sink and unchanged default path; exact original begin/progress/complete frame boundaries and fatal cleanup. The numerical engine modules and pair-log codec stay unchanged.
- `compact_training.py` and `compact_native_producer.py`: exact both-plan/job `compact_restart_retention_input` plus descriptor version/policy hash; reject unsupported local route before owner/namespace allocation; pass the admitted object, not arbitrary caller dictionaries.
- `compact_dictionary.py` and `compact_mcm.py`: instantiate the selected stage controller under the existing captured owner transition and pass it to the matcher; preserve pre-callback numerical pins, actual completion counts and existing archive writer/read flow.
- `compact_policy.py` and `compact_owner.py`: explicit new reservation computation and immutable stage intent/contract binding; stage-wide no-refund accounting; preserve old validator behavior when absent.
- `archived_stage.py`, `archive_owner_stage.py`, `archive_owner_seal.py`: new strict proof version and the actual visitor/content/seal joins described above. This is essential in addition to the earlier proposed ten-file ownership list: `archive_owner_stage` currently supplies the reader intent and cannot infer a new version later from missing files.

`compact_stage.py` can remain unchanged if only the explicitly archived route is supported and its new visitor calls a separate new-format validator. `compact_terminal.py` can remain unchanged only if its existing captured stage contract hash/reference, reservation, original ledger pin and full `_stage_content` invocation transitively bind every new retention/selection seal. Prove that with an actual original-terminal-pin mutation test; otherwise make the narrow explicit pin addition. `archive_owner_policy` needs editing only if read-reference/metadata accounting changes. Dispatcher/SSH wiring, model changes, tail/batch retention and cold native loading remain outside this slice.

`job.required_sources()` includes every package Python file. New helper/controller modules therefore alter the required source closure and must appear in a fresh committed registration and matching anchor; their mere importability is not source admission. The maintained dynamic numerical kernels remain explicitly pinned. No old numerical source hash or historical registration should be rewritten to hide the additive operational implementation.

## Decisive synthetic integration boundary

After corrected primitive acceptance, use one isolated frozen actual-owner archive fixture covering dictionary and MCM, at least three snapshots for one pair, a selected FIRST replay copy, a pair with zero snapshots, dictionary reuse/capacity, exact MCM scores and graph artifacts, owner/ledger/terminal closure and remote-forbidden post-close checks. Include actual frame/purpose/identity/ordinal mismatch, late callback mutation, failed retirement with spent writer/read/control evidence retained, duplicate no-spend, and rehashed retention metadata rejected by the original terminal pins. Keep the old format's missing-checkpoint refusal test. Separate literal numeric/feasibility assertions from provenance hashes which legitimately change under a new operational version.

This is an integration acceptance slice, not a proposed financial run or proof of physical capacity. All stage limits must be finite for its synthetic fixture; unresolved full-population RAM/disk/replay admission remains explicit. C01–C18 and all historical evidence requirements are unchanged.
