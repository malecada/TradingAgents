## Smallest correction to test first

A new immutable candidate02 can change only the two node-score expressions from einsum to the original multiply-then-last-dimension-sum:

```python
source_score = (h * self.a_source).sum(-1)
target_score = (h * self.a_target).sum(-1)
```

Keep source_score[source]+target_score[target], LeakyReLU, all masks/self-loops/ordering, original parameter construction/RNG and the already isolated custom message aggregate unchanged. This preserves the original D-axis product/sum operation per node/head instead of the einsum dot implementation. It is the smallest next engineering candidate: no new autograd rule or changed model/numeric setting. It has not been executed and is not guaranteed to pass the frozen oracle.

The original eager path performs those reductions after gathering an E×H×D tensor. The node form performs them over N×H×D before scalar gathers. Even with the same per-row arithmetic, changed strides/shape-dependent kernels or gradient accumulation grouping can affect rounding. Autograd now sums scalar edge contributions into node scores before multiplying by attention vectors; original eager attention multiplies each edge contribution and later scatters node gradients. Attention-vector gradient reduction likewise changes from edge-level contributions to node-level aggregates. These first-gradient order differences must be explicitly tested, not called bitwise preservation. The observed four-arm result does not resolve them because neither mixed arm used this proposed node multiply/sum.

Memory: the first admitted graph has N2,049,095/H4/D16. One float32 node product is524,568,320 bytes (about500.27MiB), plus N×H scalar output32,785,520 bytes. Separate source/target statements allow each product temporary to die before the next; this is a source-lifetime observation, not a measured peak. Ordinary multiply/sum autograd saves operands, including references to the already existing h, rather than necessarily retaining each full product; saved-tensor hooks must verify actual runtime behavior. Existing node h, node gradients, scalar attention, model activations, source/destination indices, allocator/cache and process overhead remain. The temporary is materially smaller than a first-layer effective-edge product814,606,080–1,339,174,400 bytes, but still large. No claim that the entire forward/backward fits3.75GiB follows.

This choice is preferred for the next unchanged tiny oracle because it minimizes new numerical code and directly tests the suspected dot-reduction distinction. It is not an empirical release recommendation before measured memory evidence. A failed next oracle is preserved; no tolerance/seed/fixture selection follows from it.

## Bounded edge-attention alternative

If node multiply/sum fails the original numerical oracle or its measured footprint is unacceptable, prepare a separately reviewed custom first-order edge-score Function. Forward iterates contiguous edge blocks B<=65,536 in original order and computes `(h[source_block]*a_source).sum(-1) + (h[target_block]*a_target).sum(-1)` into an E×H scalar-logit output. LeakyReLU can remain outside that Function. Each block uses the original elementwise multiplication and D-axis sum, avoiding einsum and full E×H×D backing. Save h/a_source/a_target/endpoints once; do not retain per-block autograd graphs or gather arrays.

For incoming derivative dE, backward computes edge contributions dE[:,:,None]*a_source/a_target and scatters to a private node gradient in original contiguous edge order. Attention-vector gradients require sum over all original edge contributions dE[:,:,None]*h[source/target]. Compute bounded blocks and accumulate in a declared fixed order; retain separate source/target gradient contributions until their combination order is defined. A single interleaved destination/source accumulation would silently change the original branch accumulation order. The baseline autograd reduction across edges and branch summation may use different grouping; summing block partials is mathematically equivalent but cannot be advertised as exact float32 gradient order. Preserving original per-edge forward expressions is therefore insufficient proof. The original first-step Adam oracle and direct all-input/all-parameter gradient checks remain mandatory.

At B65,536/H4/D16, each float32 B×H×D temporary is16,777,216 bytes. Multiple simultaneous gathers/products/incoming-gradient arrays multiply that bound; specify actual lifetimes and a conservative sum rather than quote one block as peak. E×H output/saved scalar activations still scale with graph edges, and node h/gradients still scale with N. Temporary edge attention work can be bounded without eliminating those necessary arrays. Memory audits must classify underlying backing extent, not shape alone.

The custom rule must explicitly refuse unsupported dtype/device/layout/block parameters and higher derivatives via once_differentiable, with finite zero-edge behavior and exact original endpoint checks. Full GraphAttention already becomes first-order/CPU-limited through the current message aggregate; another custom Function does not restore higher-order or GPU support. Do not use gradient checkpointing, graph sampling, reduced heads/widths, autocast or different dtype as a hidden substitute. No production implementation of this alternative is authorized by this proposal.
