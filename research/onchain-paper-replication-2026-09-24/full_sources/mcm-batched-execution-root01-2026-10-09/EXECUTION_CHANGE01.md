## Deliberately changed engineering contract

An ordered, bounded batch retains fresh occurrence purpose hashes and exact
float64 score bits, iterations and convergence. Its pending range is durably
recorded before computation. A complete chunk becomes eligible for use only
after durable write, exact readback and authenticated completion metadata.
An incomplete range stays attempted with unknown completion; it supplies no
complete-cell credit. A poisoned batch cannot continue. Names are exclusive.

The full-range driver retains one extracted local neighborhood at a time.
Collecting graph objects to fill a 4,096-cell batch is prohibited. Committing a
separate batch for each 32-motif node would instead create 12,999,004 batches and
38,997,012 final files. The streaming successor therefore consumes a declared
finite task range on demand and retains bounded purpose/score records across
centers, releasing graph references immediately after each computation.
An initial pending commitment binds the intended range and frozen workload
descriptor; it cannot claim an actual purpose aggregate that is not yet known.
Final metadata binds the aggregate computed from the actual ordered records.
Short, excessive or misordered tasks, mutation and failed publication cannot
supply complete-range credit.

The initial candidate01 is retained for review. Its per-cell JSON/hex encoding
and pending purpose list are unsuitable for the full storage target: a sample
completed record encodes to 188 bytes and one pending hex hash adds about 67 bytes.
The successor uses an actual fixed 53-byte binary record rather than describing
JSON as a compact binary format. The 415,968,128 records alone require
22,046,310,784 bytes, excluding chunk framing/metadata and all other stores.
Local capacity still does not admit the full workload; external streaming,
reservation and actual recovery remain requirements. No speed or capacity claim
follows from this encoding calculation.

boundary callback, completion can use a stale in-memory pending hash. The new
candidate must reproduce that failure first, retain the original source and raw
failure, and refuse actual pending-body/root replacement before publication and
cell credit. Current pending, temporary and final bytes/extent/identity must join
the pinned namespace. This is a correction to the changed seam, not a new
generic launch or security framework.

Source/Owner checks move to explicit batch/checkpoint boundaries instead of

## Evidence required before use

Focused tiny synthetic checks must establish numerical agreement under the
already frozen tolerances, unchanged operation/checkpoint ordering, exact
purpose/score encoding, interrupted-range disposition, exclusive names,
corruption refusal and cleanup. Different-author review must examine the
changed seam and its failure order. Source acceptance alone does not admit a
real-data measurement.

Root integration must join genuine imported dictionary/source ancestry,
registered inputs, native limits, installed runtime, output consumption and
checkpoint restoration. Commit and review the concrete new entry plus a
same-family cumulative allowance before empirical execution. Preserve/recover
actual increments using the already accepted tools; do not recopy old stores.

The full workload still needs measured numerical throughput, full physical-store
reservation and output/tail streaming or offload. Batching has no demonstrated
orders-of-magnitude speedup. The active diagnostic's memory and storage do not
prove full MCM or neural-training capacity. Scientific completion still requires
all seven complete MCMs and a real GAT → attention LSTM joint update/checkpoint.
