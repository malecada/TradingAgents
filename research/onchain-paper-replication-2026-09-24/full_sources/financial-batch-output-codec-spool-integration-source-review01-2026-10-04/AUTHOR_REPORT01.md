# Codec-to-spool engineering byte routing

Candidate router04.py implements a concrete lossless routing adapter around the exact accepted codec f10f6803, LocalStore ceec6144 and spool05 704e26d5. All six copied source modules are byte/AST identical, and all four original preparation/review manifests were authenticated by complete membership, literal mode, body hash and literal link target. Genuine Target/Owner/Binding/Produced/durable authority source bodies are pinned and unmodified, never imported or impersonated by the engineering target_key.

The adapter first authenticates an actual complete codec directory with the original verifier, exact external terminal pin and immutable descriptor bytes. It enumerates start.json, each original framed chunk and corresponding page in codec emission order, then terminal.json. Each row records complete-file size/hash/literal mode and the authenticated raw offset, length and hash; the immutable descriptor retains dtype, role, C order, shape and every scope pin. No frame header, payload, trailer, chunk size, page count, scientific raw framing or model batch is changed. The start/page/footer bytes are routed and recovered, not merely counted.

A complete ordered inventory is partitioned into at most32 members per retained spool plan, below the unchanged4096 cap. Every plan uses its original full-file size/hash and retains exact target/inventory/partition/ordinal mappings. Whole route reconstruction rejects missing, duplicate or reordered partitions and malformed descriptors/offsets. Cross-plan and cross-target reuse is rejected through an exact immutable envelope pin in addition to the spool's exact typed acknowledgment. The complete intent stores each original inventory once and partition references rather than redundant repeated row descriptions; source payload bytes are untouched.

One shared ledger consumes conservative whole-target logical/allocated accounting before intent, callbacks or output writes. It charges original codec files, every retained spool copy and event slot, every recovered codec duplicate, complete routing intent, finite begin/done/failure journals, root/entry allowances and48MiB IO headroom. Limits and consumed totals are read-only public properties; no successful acknowledgment, failure, target transition or partition completion refunds or resets them. The observed10GiB disk floor and filesystem fragment assumptions are checked. These are conservative engineering accounting units and samples, not actual remote reservations, universal filesystem quotas, live-watch coverage or native memory measurement.

The actual tiny pipeline encoded both supported dtype/role descriptors using opaque bytes, enumerated95 genuine fixture files across14 retained partitions, transferred each unchanged through the real Spool utility into a second real LocalStore, and passed complete codec raw reassembly plus full recovered file/mode/order/offset comparisons. Nothing was interpreted as numeric data. Callback buffers are explicitly in-memory engineering readbacks, not a network, independently authenticated origin or typed research recovery. Completed spool files remain physically retained and are checked again after their descriptors close and before later completion. Source/current membership and ledger immutability are checked throughout. Every failed run retains attempted files/journals, absent complete.json and unattempted partition suffixes; failed and finished instances cannot retry.

Controls refuse original-source extras/missing/corrupted frames, wrong scope/dtype/offset, malformed/reordered/duplicate routes, reservation shortfall, partition/cardinality/type changes, partial transfer, mismatched or cross-envelope acknowledgments, wrong recovered bytes, attempted reservation refund, mutation of an earlier closed spool, original MemoryError with later fatal cleanup, and cleanup-only fatal uncertainty. The first router01 execution failed before routing because immutable descriptor bytes lacked a JSON representation; original source, traceback and encoded fixtures remain. router02 uses explicit lossless hexadecimal metadata for those bytes. router03 adds read-only accounting and closed-spool checks. router04 additionally removes redundant descriptor repetition from the routing intent and asserts the whole aggregate raw denominator.
