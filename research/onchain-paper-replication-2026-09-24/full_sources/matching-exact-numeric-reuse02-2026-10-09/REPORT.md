## Changed source-check contract

Construction and explicit `begin_batch()`/`end_batch()` attest every frozen source body and the complete captured function/code roster. Real checkpoint callbacks receive the same full attestation immediately before and after the callback. Occurrences are refused outside an active batch. `close()` attempts final attestation for an active unpoisoned batch, then always clears retained entries. Boundary failures poison and clear; an engine/checkpoint failure propagates through the original executor cleanup before wrapper poisoning.

Per-occurrence checks are deliberately limited: matching config, policy, schedule and callback bindings; fixed selected function/code identities; direct primitive identities; default NumPy/fenv modes; and the unchanged fresh pair/public identity validation. They do not rescan source files or the whole function roster. Source/runtime changes outside those lightweight pins can go undetected until a declared boundary. Returned occurrence receipts are provisional until successful end_batch; the caller must not publish final batch credit before then. Trusted frozen numerical runtime and exclusive state/input ownership inside the interval are requirements, not newly established authority. This is not continuous source verification or protection against hostile private-state/transitive native mutation.

## Fixed indexed LRU and retained memory

A fixed slot list and fixed signed-int arrays store power-of-two bucket heads, doubly linked bucket chains and LRU links. A SHA256-derived64-bit routing value chooses a bucket; exact key bytes still decide equality, so even a routing collision never equates different numerical pairs. Lookup visits only that bucket's chain, with actual probe counters. Adversarial/all-colliding keys can require up to the finite entry bound4096 probes; constant worst-case lookup is not claimed. LRU touch and each eviction use a constant number of link updates, with no whole-slot shifts. No dictionary copying or resizing is used.

Retained cache bytes are incrementally accounted: measured fixed list/array objects plus measured entry/key/value/hash/primitive objects. Entry admission/eviction checks this allowance before retaining the new entry; reads of retained_bytes are O(1). Counter/accounting correctness is independently recomputed once in the synthetic harness, never in the occurrence hot path. The same64MiB cache/8MiB exact-key/4096-entry hard caps apply. Key construction, bounded source-read buffers, runtime/config pins, counters, one occurrence receipt and original numerical state remain outside the cache-object allowance; it is not process RSS or allocator-arena capacity.

Counters expose source_guard_calls, source_hashed_bytes, key_hashed_bytes, lookup_probes, lru_link_updates, evictions and accounted_cache_bytes. Source bytes count this wrapper's attestation; key bytes count its routing SHA input. They do not claim to count hashing performed by unchanged graph-identity or numerical-engine calls. Evictions include explicit failure/close clearing. Exact keys are still built from graph bytes per occurrence; this candidate does not cache input currentness across calls.
