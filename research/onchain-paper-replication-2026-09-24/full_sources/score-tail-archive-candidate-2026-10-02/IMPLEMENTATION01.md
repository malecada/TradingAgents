# Bounded score-tail archive engineering candidate

This isolated source candidate implements an exact 80-byte score-tail reader, retained local chunk writer/seal, separate tail-population arithmetic and a source-bound genuine-held Owner boundary. It does not yet implement the shared tail reservation/transport capability or replace the live stream reader. Consequently it frees **zero production bytes** and is not an executable external offload release. No production source, raw evidence, historical claim, job, numerical method, selected motif or empirical outcome changed.

## Implemented behavior

`score_tail_archive.py` validates the original `<Qd32s32s` records without importing NumPy/Torch. Every global ordinal, float64 score bit pattern, purpose hash and predecessor checksum is retained. It joins the original complete tail start/terminal, exact next batch destination and float64 chunk header/payload. It rejects failed/pending tails, incorrect denominator/order, unknown fields, noncanonical metadata, nonfinite/out-of-range values and mismatched content. Chunk count is explicitly at most65,536, making a full tail5,242,880B, under8MiB. Bounded descriptor reads/writes use at most64KiB per syscall. Total Python memory remains multiple bounded chunk buffers, not64KiB overall.

The prospective versioned contract pins original owner/stage/source/job/Binding, graph/node order, exact ordered32 motif identities, dictionary and original scientific matching hash separately from current execution matching/workload scope. The contract is a trusted input, not proof that an arbitrary caller supplied real motifs or that purpose hashes arose from actual neighborhoods. Those science derivations remain the imported kernel/stream/stage admission's responsibility. The predecessor mapping is bound as a field; a whole-stream chain traversal is not implemented here.

`LocalChunk` creates an exclusive owned directory; persists detached contract and exact original tail/batch bytes; and publishes a receipt only after complete local verification. The final receipt is made visible with an exclusive hardlink from a fully written/fsynced pending file, followed by removal of that invocation's own successful pending hardlink. Readers reject the temporary two-link state. Existing target bytes are never overwritten. Failure retains pending and partial files. Directory/member identity, regular file type, single-link alias refusal, immutable body hash, lease revocation, original contract mutation, exact inventory and final rechecks are enforced. Each descriptor is closed once. The first fatal exception object survives independent cleanup failures; nonfatal cleanup uncertainty becomes worker-fatal. Original source tails are never unlinked. Local receipts explicitly say `local-bytes-verified-only` and `remote_verified:false`.

`held_tail_adapter.py:HeldSource` uses actual production `Owner`, `Stage` and `_HeldTransition` types, the captured original token and original object identities. It does not synthesize a lock or accept an unlocked public callback as authority. It joins the actual resource Binding's job_input/job_sha256/resource_only and current source, original stage intent/inode/workload/rows×32 denominator, and exact original stage stream paths. After external authority callbacks, the original tail, batch header/payload and batch-start bytes/inodes are rechecked. This is a source candidate only: its real Owner path has not been imported/executed in a native fixture. It depends on the separately reviewed resource Binding correction; ordinary production Binding lacks these resource fields and is refused.

`tail_population.py` computes a distinct all-target80-byte population including exact32 columns, partial final chunks, duplicate graph refusal, aggregate chunks, remote body bytes, rounded transfer bytes and commands. Its defined pattern is one upload, one immediate full readback and1–1024 extra recovery sweeps. Read transfers retain the existing `(bytes//32768+1)*32768` rounding, including the extra block on exact multiples. The result is required capacity, not a durable reservation or permission. It must be combined with pair-event and other populations across all representations in the original shared job ledger before the first transfer.
