## Interfaces and state

- `FuturesClient.market_order(..., client_order_id=None)` includes `newClientOrderId`; the executor supplies a persisted stable ID. `order_status(symbol, client_order_id)` queries completed as well as working orders. `book_ticker()` returns exchange-timestamped bid/ask rows. `BinanceAPIError.execution_unknown` separates uncertain execution from definite rejection. Only GET requests may automatically retry; an order POST never does.
- Durable append-only `order_state_v2.jsonl` records submission intent before POST, then rejection, unknown status or exchange status. An executor lock serializes cron/manual actions on the same host. Unknown/working orders must be resolved by status lookup before new submissions. A negative lookup after a lost response remains unknown; it is not sufficient proof to resubmit. State corruption fails closed.
- `journal_live_v2.jsonl` distinguishes intent, incomplete and reconciled states; recorded quantities are frozen for an incomplete daily batch. Reconciled completion requires the actual positions to match those quantities, and no unresolved order remains. Subsequent wakes check actual positions before skipping. Dust intentionally retained in the initial plan is recorded in its target. Rejections remain retryable through a new residual intent; filled legs are not resubmitted.
- `journal_dry_v2.jsonl` is independent of live completion, day-equity seeding, fills and order intents. Dry runs perform read-only account/quote checks and do not set leverage or place orders.
- The account must explicitly report one-way mode before ordinary or emergency orders. Emergency closure writes the halt flag first and records actual residual exposure in `closure_v2.jsonl`; failure never reports a successful flatten. A halted ordinary run makes no order attempts; `close-all` retries closure while keeping the halt flag.
- Ordinary sizing requires yesterday's signal with today's explicit trade day, corrected paper version 2, finite positive complete desired marks at most 600 seconds old, and current bid/ask quotes for every held or desired symbol at most 90 seconds old. Missing desired marks cannot be interpreted as departure. The 5% per-name cap is enforced for all book sizes; tiny exchange fixtures explicitly substitute a test-only policy. Frozen unfilled targets remain in the quote/risk universe when a later input row omits them. The risk envelope includes maximum held/target exposure per symbol, so a failed departure cannot leave uncounted exposure when additions are considered. Emergency reduce-only closure is independent of marks.
- `live_exec.diff_orders(..., unavailable=...)` permits callers to preserve an explicitly unavailable target. The CLI additionally suspends a batch with missing desired marks/filters or missing held quotes.
- `todays_book(..., trade_day=None)` and `journal_one(..., trade_day=None)` expose the decision date. The CLI always supplies today's UTC date; the helper default infers the next day for deterministic local panels. Signal construction and calendar membership call `opt.build_signal` and `opt.monthly_universe`. Missing current signals do not write a flatten instruction.
- The paper paths are now `journal_v2.jsonl` and `journal_champion_v2.jsonl`. Legacy journal content is rejected even when a caller supplies a custom path. Each corrected row carries `journal_version=2`, shared `accounting_version`, the explicit trade day, base/overlay NAV and marked notionals, measured gross/funding/cost/net/turnover, actual prior scale, and coverage reasons. The newest row settles the prior row's daily target with the shared `accounting_step`, using simple returns, pretrade-NAV sizing and one turnover fee. Overlay sizing uses the last 20 contiguous measured **base net** daily returns. Gross close/mark returns remain labelled diagnostics and do not enter sizing.
- Both normal online-panel loading and offline-panel loading attach observed rates from the existing local `xsect/funding/{symbol}.parquet` store. `load_observed_funding` never writes or fetches data. It requires a complete daily event grid and next midnight boundary print. A smallest supported 1/2/4/8-hour interval is inferred from prior-seven-day prints, and that assumption is recorded as `observed_cadence_inference`. Missing files, missing events, unsupported cadence or conflicting timestamps yield missing funding, not zero. Public paper marks use bid/ask midquotes only when the exchange timestamp is present and at most 90 seconds old; missing timestamps never become a fresh observation.

## Limits requiring explicit treatment

The local funding store contains no historical exchange schedule vintages. The cadence check is conservative event coverage under a disclosed inferred schedule; it cannot prove that an unrecorded exchange schedule change never occurred. A stale store, missing quotes or missing held prices makes measurement incomplete. A missing prior net account state or journal gap is not silently restarted; a new explicitly versioned measurement segment or reviewed append-only recovery would be needed. Historical gross journals and saved performance remain untouched.

An unknown order that remains absent from exchange lookup is intentionally never automatically resubmitted. An operator must reconcile exchange/account evidence before resolving that intent; deleting an intent to bypass this check is unsafe. The lock is local to one host, so the executor still assumes a dedicated account with no other machine submitting competing orders. Transport disconnects, crashes and unavailable position snapshots cannot establish completion. The conservative risk envelope can suspend a rotation or an already oversized book; verified emergency closure remains a separate command.

No v2 deployment was performed. Offline success demonstrates corrected local behavior and arithmetic; it does not establish forward measurement coverage, exchange availability, deployment health, profitability or strategy validation.
